## 2. 꼭 지킬 규칙

1. **지금 업무 방식은 언급하지 않는다.** 누가 어떻게 짜는지, 업체·수작업·이전·이후 비교를 쓰지 않는다. 2025년 KBO 실제 일정과 비교하는 화면·숫자도 쓰지 않는다(독자가 그 일정을 만든 사람들이다).
2. **부르는 말**: 독자는 **운영자**, 시스템이 일정을 짜는 일은 **자동 편성**. 「엔진」이라는 말은 쓰지 않는다.
3. **아직 없는 기능은 「지원 예정」**으로만 적는다: 시즌 중 다시 짜기. 특정 날짜 홈 불가(구장 대관 등)는 지금 고려하지 않으므로 적지 않는다(있는 기능은 특정 날짜 홈 지정).
4. **개발자 용어 금지**: JSON, 파일 이름, 시드, hard/soft, 데이터셋, 벌점 계산식(넘은 폭의 제곱 등).
5. **화면 이름은 화면 그대로, 굵게.** 화면 글을 먼저 확인하고 쓴다(`ui/app/studio/`). 2026-11-07에 화면 글을 바꿨다: 「엔진」→「자동 편성」, 「나머지 엔진으로 짜기」→**「나머지 자동 편성」**, 「시험 엔진」→「시험용 자동 편성」, 「편성 스튜디오」→**「매치봇 스튜디오」**.
6. **결론 먼저, 제목은 짧게, 설명은 그 밑 줄에.**
7. **중심 구도**: 자동 편성은 안을 내고, 운영자가 설정하고, 비교해 고르고, 확정한다. 근거 문장은 운영 방침 설명 창(`objective-help.js`)의 말을 그대로 쓴다 — "좋은 균형점은 여럿이고, 그 가운데 어디에 설지는 자동 편성이 정하지 못합니다."

### 형식 규칙

## 4. 2장 「매치봇 스튜디오가 하는 일」

- **2.1 자동 편성이 하는 일**: 반드시 지키는 규칙을 하나도 어기지 않는 일정을 만들고, 그 가운데 운영 방침의 순서와 허용 수준으로 더 나은 것을 찾는다(실행 1~5분, 기본 2분). 실행할 때마다 결과를 남겨 비교할 수 있다.
- **2.2 운영자가 정하는 일**: 조건(맞는지 확인, 「추정」부터), 방침(순서·허용 수준 — 이동 격차와 주말·공휴일 격차는 한쪽을 줄이면 다른 쪽이 벌어진다), 확정(시즌 일정으로 쓸 것을 고름).
- **2.3 운영자가 설정하는 것**: 자동 편성은 **운영자가 설정한 것만 안다.** 중계·구단 사정 같은 화면 밖 사정은 설정으로 바꿔 알려 줘야 반영된다. 설정은 세 갈래다.

| 갈래 | 무엇인가 | 화면 | 잘 설정하는 원칙 |
| :--- | :--- | :--- | :--- |
| 사실 | 이미 정해진 것 | 구장·거리, 개막일, 올스타 휴식기, 1차 편성 종료일, 쉬는 요일, 공휴일과 가중치, 홈 경기 수, 맞대결 수 | 정확하게. 「추정」 표시부터 확인 |
| 지정 | 꼭 이렇게 되어야 하는 것 | 개막 2연전 대진, 어린이날 홈, 아무 날 「홈 구장 지정」·「대진까지 고정」, 결과에서 연전 고정 | 꼭 필요한 것만. 많이 고정할수록 찾을 여지가 줄고, 너무 많으면 처음부터 다시 짜지 못한다 |
| 방침 | 무엇을 먼저 챙길지 | 우선순위 순서, 허용 수준(기본 이동 횟수 4회·이동 거리 600km·주말·공휴일 3점), 실행 시간 | 기본값으로 한 번 → 결과에서 「넘음」 확인 → 조금씩 바꿔 다시 실행 → 비교. 0이면 반드시 맞추려 하고, 기본값의 3배를 넘기면 사실상 보지 않는다 |

그림 하나: 「자동 편성」과 「운영자」 두 칸에 각자 하는 일.

## 5. 3장 「처음 한 번 따라 하기」(설명회에서 그대로 시연)

2027 편성 조건, 실행 시간 **1분**, 2025 보기는 쓰지 않는다.
1. 처음 화면 → **새 계획 만들기** → **검토 시작**
2. 편성 조건 4단계를 차례로 **수락**(「추정」 확인법을 한 번 보여 줌)
3. 기본 방침 **「이동 격차 줄이기 우선」**으로 실행
4. **현재 결과 분석**: 요구 사항 점검, 목표마다 「안」·「넘음」
5. 방침을 **「주말·공휴일 격차 줄이기 우선」**으로 바꿔 다시 실행
6. **실행 결과 비교**: 두 버전을 골라 「여기서 갈림」 읽기
7. 하나를 **확정**(「확정 취소」로 되돌릴 수 있음)

배우는 것: 방침에 따라 결과가 달라진다, 고르는 사람은 운영자다.

## 6. 4·5장의 설정 상자와 9장

### 6.1 설정 상자(설정마다 같은 모양)
**무엇을 정하나 · 기본값 · 바꾸면 얻는 것과 내주는 것 · 언제 바꾸나 · 결과에서 확인하는 곳**

### 6.2 설정 목록(현재 화면 기준, 2026-11-07 코드 확인)
- **구단 정보**: 구단명, 구장(Enter = 위치 찾기), 위도·경도(읽기 전용, 「지도에서 찍기」), 다른 구장까지 거리(km), 「도로거리 받기」. 「없어요 — 그대로」/「있어요 — 고칠게요」. LG·두산 구장은 「서울 올림픽 주경기장」으로 미리 고쳐 둠.
- **시즌 기간·연전 묶음**(줄마다 「수락」/「수정」): 쉬는 요일(기본 월), 개막일(2027-03-27 토, 토요일만), 올스타 휴식기·후반기 첫 4연전(7/9부터 6일, 1~14일), 1차 편성 종료일(9/5, 「자동으로」), 홈 경기 수(격년 홈 73/71), 달력 고치기(묶음 만들기·연전 수 바꾸기·나누기·지우기).
- **주요 이벤트 일정**: 개막 2연전 홈(홈 구단 잠김, 상대만 고름, 「전년도 순위대로 되돌리기」), 어린이날 홈(5곳, 두산·LG 중 하나만), 고른 날 「홈 구장 지정」(「대진까지 고정」/「홈 구장만 지정」, 하루 5곳), 공휴일과 가중치 표(공휴일 2·어린이날 3, 0~10, 「법정 공휴일 채우기」). 주말 1점은 고정.
- **확인**: 맞대결(16), 그중 1차 편성(15), 1차 편성 홈(9), 연전 최소 길이(3), 후반기 첫 4연전 홈, 격년 홈 73/71.
- **운영 방침·실행**: 「이동 격차 줄이기 우선 (기본)」/「주말·공휴일 격차 줄이기 우선」/「직접 정하기」(1~3순위만 바꿈, 「전체 이동 거리」는 늘 마지막). 허용 수준: 이동 횟수(4회, ±1), 이동 거리(600km, ±50), 주말·공휴일 홈(3점, ±1). 실행 시간 최대 1~5분(기본 2분). 「이 방침으로 실행」/「멈추고 이 결과 쓰기」. 「운영 방침 설명하기」. 이어서 짤지 처음부터 짤지는 자동으로 정해진다.
- **결과 고치기**(일정 자세히 보기): 「고정」/「홈 지정」, 「모두 풀기」, 「옮기기…」/「고정 풀기」, 「검사하고 저장」, **「나머지 자동 편성」**.
- **실행 결과 비교**: 운영 방침 고르기(순위 기준), 비교 체크(최대 2개), 「확정」/「확정 취소」(해마다 하나, 시험용 결과·규칙 어긴 결과에는 없음), ⋯ 「불러오기」·「내려받기」·「이름 바꾸기」·「지우기」(되돌릴 수 없음, 확정본은 못 지움).

## 7. 6·7장: 결과 읽기·비교·확정

목적: 운영자가 「이 결과를 왜 골랐는지」 한 줄로 말할 수 있게 한다.

**6장 읽는 순서**: ① 요구 사항 점검(서버가 완성된 일정을 날짜별 경기로 풀어 자동 편성의 점수와 따로 다시 센다, 어긴 항목이 있으면 멈춤) → ② 방침과 견주기(목표마다 「안」·「넘음」) → ③ 구단별 보기(한 구단에 몰린 부담) → ④ 일정 자세히 보기(달력·연전, 결과 고치기).

**7장**: 순위표(모든 버전을 지금 운영 방침의 순서로, 규칙을 어긴 결과는 저장되지 않음) → 두 버전 비교와 「여기서 갈림」(처음 승부가 난 줄 = 왜 이쪽이 위인가) → 확정 → 내보내기(엑셀은 「요구 사항 점검」의 **엑셀로 받기**뿐 — 연전 기간별·날짜별 출전표·근거 표. 버전 자체는 ⋯ **내려받기**/**받은 버전 올리기**로 주고받음. 2026-11-07 화면 확인: 버전을 엑셀로 내보내는 단추는 없음).

**확정 전 확인 목록**(7장 끝, 요약 카드에도 그대로)
1. 요구 사항 점검에서 어긴 항목이 0개인가
2. 1순위 목표가 「안」인가, 「넘음」이 있다면 받아들일 수 있는 정도인가
3. 구단별 보기에서 한 구단에 몰린 부담이 없는가
4. 지정한 것(개막 2연전, 어린이날 홈, 홈 지정, 고정한 연전)이 그대로 들어갔는가
5. 비교한 버전과의 「여기서 갈림」을 보고 이 버전을 고른 이유를 한 줄로 말할 수 있는가

## 8. 10장 문제 해결의 증상
- 「이 방침으로 실행」이 눌리지 않음 → 사전 점검에 진행 불가 항목(예: 잠실을 같이 쓰는 두 구단의 홈 겹침)
- 실행이 끝났는데 목표가 「넘음」 → 허용 수준이 너무 좁음
- 「처음부터 다시 짜지 못해 지금 일정에서 이어서 풀었습니다」 → 고정한 연전이 너무 많음
- 「시험용 자동 편성」 띠 → 편성 서버에 연결되지 않음(확정할 수 없음)
- 「자동 편성 오류」 알림

## 9. 13장 자주 묻는 질문
1. 같은 조건인데 왜 결과가 조금씩 다른가요? (고장이 아니다 → 그래서 비교해 고른다)
2. 실행 시간을 늘리면 결과가 더 좋아지나요?
3. 허용 수준을 0으로 두면 어떻게 되나요?
4. 확정한 뒤에도 바꿀 수 있나요?
5. 특정 날 구장을 쓸 수 없으면? → 지원 예정
6. 편성 서버 없이도 쓸 수 있나요? → 시험용이라 확정은 할 수 없음

## 10. 만드는 방식

- **원고**: `docs/manual/src/`에 장마다 Markdown 한 파일(`00-cover.md` … `14-help.md`, 요약 카드 `card.md`).
- **PDF**: 저장소 안의 문서 페이지(HTML)로 모아 크롬으로 인쇄한다. 제목 계층에서 책갈피·목차가 생기게, 문서 언어 한국어.
- **화면 캡처**: 편성 서버에 연결한 상태(「시험용 자동 편성」 띠가 없게), 2027 편성 조건, 1440 너비, 필요한 부분만 잘라 번호 표시. 원고의 `[그림 n: …]` 자리에 넣는다.
- **순서와 모델**: 본문 집필은 Fable 세션 — 2 → 3 → 6·7 → 4·5 → 9·10 → 11~13 → 0·1·14 → 요약 카드. 화면 캡처·PDF 조판·화면 이름 대조는 Opus.
