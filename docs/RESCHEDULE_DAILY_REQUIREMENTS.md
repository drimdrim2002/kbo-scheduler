# 날짜 단위 재편성 요구 사항

- 정리한 날: 2026-11-07
- 상태: 요구 확정. 엔진(`docs/RESCHEDULE_DAILY_ENGINE_DESIGN.md`)과 결과 화면(B안: 취소 경기 → 기간·조건 → 결과, 결과에 달력 보기), §8 다시 짜기(기본안: 발표 → 1쪽 달력에서 발표한 경기 취소 → 2쪽에서 다시 짜기)를 구현해 main에 병합했고(2026-11-08), 서버에 연결해 실행을 확인했다
- 이 문서는 `KBO_OPUS_UI_REQUIREMENTS.md` §5.8(FR-P)·§6.3(RH/RS)의 재편성 정의를 바꾼다. 그 문서의 「같은 대진의 잔여 경기를 1~3경기 시리즈로 묶어 배치」(FR-P5)는 더 이상 쓰지 않는다.

## 1. 한 줄 정의

1차 편성(연전 단위, 구단당 135경기)이 끝난 뒤, **취소 경기 + 잔여 경기**를 사용자가 정한 기간에 **날짜 하나하나** 배정한다. 결과는 「날짜마다 열리는 대진과 구장」이다.

## 2. 배정 대상

| 항목 | 내용 |
| :--- | :--- |
| 시즌 경기 수 | 구단쌍당 16경기, 구단당 144경기, 리그 720경기 |
| 1차 편성 | 구단쌍당 15경기, 구단당 135경기(연전 단위) |
| 잔여 경기 | 구단쌍당 1경기 = 구단당 9경기, 리그 45경기 |
| 취소 경기 | 1차 편성 경기 중 우천·폭염 등으로 열리지 못한 경기. 대진과 홈팀은 그대로, 날짜만 비어 있다 |
| 배정 대상 | 잔여 경기 + 취소 경기 (예: 취소 30경기 → 75경기) |
| 취소 경기의 홈 | **원래 홈팀 그대로** |
| 잔여 경기의 홈 | 홈 73/71 원칙(`settings.homeTotals`, 구단별 「전체 홈 − 1차 편성 홈」) |

## 3. 언제 짜나

- **1차 편성 기간이 모두 끝난 뒤** 한 번에 짠다.
- 시즌 중 새 취소가 생기면 **입력을 고쳐 다시 실행**한다(§8). 엔진은 언제나 「비어 있는 기간 + 배정할 경기 목록」 하나만 다룬다.

## 4. 꼭 지키는 규칙 (Hard)

| 코드 | 규칙 | 기본값 | 수정 |
| :--- | :--- | :--- | :--- |
| DH-1 | 한 구단은 하루 1경기. 더블헤더 날만 같은 상대와 2경기(하루 3경기는 없음) | - | - |
| DH-2 | 한 구장은 하루 1대진. 잠실(두산·LG)은 같은 날 둘 다 홈일 수 없다 | - | - |
| DH-3 | 모든 경기를 기간 안에 배정. 기간 시작 = 1차 편성 마지막 날의 다음 날, 끝 = 사용자가 정함 | 시작: 1차 마지막 날 + 1 | 시작·끝 모두 |
| DH-4 | 연속 경기일 상한. 쉬는 날 없이 이어서 경기하는 날 수(더블헤더 날은 하루로 센다) | 6일 | 가능 |
| DH-5 | 구단당 더블헤더 상한. 모든 구단 같은 값, 0이면 더블헤더 없음 | 2번 | 가능 |

- 월요일 경기는 **허용**한다(금지 규칙이 아니라 §5의 기준으로 줄인다).
- 연속 경기일(DH-4)은 기간 앞의 실제 경기에서 이어서 센다. 예: 직전 6일 연속 경기한 구단은 기간 첫날 쉬어야 한다.

## 5. 좋은 일정의 기준 (Soft)

위가 먼저다. 위 기준이 같을 때만 아래 기준을 본다. **1~5의 순서는 1차 편성의 「운영 방침」처럼 사용자가 자유롭게 바꿀 수 있고**, 아래가 기본 순서다.

| 기본 순위 | 기준 | 판정 범위 | 허용 기준(기본값) |
| :--- | :--- | :--- | :--- |
| 1 | 구단별 마지막 경기일 맞추기 — 가장 늦게 끝나는 구단과 가장 먼저 끝나는 구단의 차이 | 시즌 전체 | 3일 이내면 벌점 없음(수정 가능) |
| 2 | 이동 공정성 — 구단별 이동 횟수·이동 거리의 차이 | **144경기 전체**(1차 + 재편성) | 그 1차 편성 버전의 운영 방침 허용 차이 |
| 3 | 재편성으로 늘어나는 이동 거리 합계 | 재편성 부분 | - |
| 4 | 월요일 경기 수 최소 | 재편성 부분 | - |
| 5 | 더블헤더 수 최소 | 재편성 부분 | DH-5 상한 안에서 |

- 3번은 2번의 부작용을 막는다. 144경기로 공정성을 보면 1차 편성의 차이를 메우려고 일부러 먼 원정을 넣을 수 있는데, 공정성이 허용 범위 안에 들어오면 엔진이 이동 합계를 줄이도록 한다.
- 1번은 「같이 끝나기」만 본다. 「빨리 끝나기」는 보지 않으므로 모든 구단이 마감일 근처에서 끝날 수 있다(마감일은 사용자가 정함).
- 1번 때문에 남은 경기가 적은 구단은 경기 사이가 길게 빌 수 있다. 필요하면 나중에 「최대 연속 휴식일」 규칙을 더한다(이번 범위 아님).

## 6. 이동 계산

- **1차 편성 부분**: 원래 일정대로 센다. 취소된 경기도 그 구단은 그 구장에 갔다고 본다. 1차 편성의 기존 규칙(올스타 휴식기처럼 3일 이상 경기 없는 구간은 0km)은 그대로다.
- **재편성 부분**: 경기한 날마다, 직전에 경기한 구장에서 그날 구장까지의 거리를 센다. **쉬는 날이 3일 이상이어도 그대로 거리를 계산한다**(0km로 보지 않는다).
- 재편성 첫 경기는 1차 편성(또는 이미 치른 재편성 경기)의 마지막 구장에서 출발한다.
- 이동 횟수: 직전 경기 구장과 다른 구장에서 경기하는 날마다 1회. 쉬는 날은 이동으로 세지 않는다.

## 7. 입력

| 입력 | 방법 |
| :--- | :--- |
| 1차 편성 결과 | 스튜디오에 저장된 버전 중 하나를 고른다 |
| 취소 경기 | **스튜디오 달력에서 날짜를 눌러** 그날 경기 중 취소된 것에 표시하고 사유(우천·폭염·미세먼지·그라운드 사정·기타)를 고른다 |
| 기간 | 시작일(기본 1차 마지막 날 + 1), 마감일 |
| 설정 | 마지막 경기일 허용 일수(3), 연속 경기일 상한(6), 더블헤더 상한(2), 기준 순서, 이동 허용 차이(1차 운영 방침 값) |

엑셀로 취소 경기를 올리는 기능은 이번 범위가 아니다.

## 8. 다시 짜기

- 이미 치른 경기(1차 + 재편성)는 고정한다.
- **이미 발표한 재편성 일정은 그대로 두고, 새로 취소된 경기만 빈 날에 끼워 넣는다.** 「전부 다시 짜기」는 만들지 않는다.
- 연속 경기일과 출발 구장은 이미 치른 경기를 이어서 따진다.

## 9. 다 들어가지 않을 때

- 들어가는 만큼만 배정하고, **못 넣은 경기와 그 이유, 고칠 곳**을 보여 준다.
  - 예: 「LG–KIA 1경기를 넣을 날이 없습니다. LG가 9/20~9/28 매일 경기라 연속 경기일 상한에 걸립니다. → 마감일을 늦추거나 더블헤더 상한을 늘려 보세요」
- 엔진은 사용자가 정한 꼭 지키는 규칙(마감일·연속 경기일·더블헤더 상한)을 스스로 풀지 않는다.

## 10. 결과 화면

이번에 만드는 것:

1. **구단 × 날짜 표**: 줄 = 10개 구단, 칸 = 날짜. 상대·홈/원정·휴식·더블헤더 표시. 연속 경기일과 마지막 경기일이 한눈에 보인다
2. **날짜별 경기 목록**: 날짜마다 대진과 구장(발표용 일정표 모양)
3. **평가 숫자**: 마지막 경기일 차이(허용 안인지), 구단별 이동 공정성, 늘어난 이동 거리, 월요일 경기 수, 더블헤더 수
4. **못 넣은 경기와 이유**(§9)
5. **엑셀 내보내기**: 1차 편성 내보내기를 날짜 단위로 넓힌다

다음으로 미루는 것: 여러 실행 결과를 순위표로 비교하는 기능(1차 편성의 「실행 결과 비교」와 같은 것).

화면 모양은 저장소 규칙대로 기본안 1개 + 대안 2~3개를 별도 worktree에 만들어 사용자가 고른다.

## 11. 기존 코드와의 관계

- **Java 엔진**: 재편성 모드가 없다. 날짜 단위 재편성을 새로 만든다(서버 엔진).
- **`ui/core/reschedule.js`**: 지금은 1~3경기 묶음(unit)을 놓는 브라우저용 임시 재편성이고 기준(RS-1~3)도 다르다. 이 문서의 방식으로 바꾼다. 서버 API 모양이 바뀌면 `fixtures/`도 같이 고친다.
- **`docs/KBO_PLAYGROUND_PRODUCT_DEFINITION.md` §3.3**: 「시즌 중 재편성」을 뺀 것에서 이번 범위로 옮긴다.
