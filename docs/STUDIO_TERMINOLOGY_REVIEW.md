# 편성 스튜디오 용어 검토

2026-10-25 · 대상: https://schedulelab.kr/studio/ 의 모든 단계(① 데이터 준비 ~ ④ 품질·배포), 시즌 운영, 설정·구글 시트·재생기 창.
실제 화면에 보이는 문구 약 1,200줄을 모아 개발자 말투를 골라냈다. **2026-10-25 추천안대로 앱 전체에 적용했다(브랜치 `claude/studio-terms`).** 시트 이름표는 `ui/app/studio/base.js`의 `S.SHEET_NAMES`·`S.SHEET_ALIASES`에 있고, 예전 용어가 다시 들어오면 자체 점검(`ui/app/studio/selftest.js` 일반 모드 금지어 검사)이 잡는다.

## 원칙

1. KBO 담당자와 팬이 매일 쓰는 말을 쓴다. 3연전, 주중·주말, 대진, 홈·원정, 우천 취소, 더블헤더, 휴식기 같은 말이다.
2. 개발 용어는 지운다. 슬롯, 시트·행·열·셀, 인스펙터, 풀, 핀, 스냅샷, 엔진, 프리셋, 목업, Δ가 여기에 해당한다.
3. 규격서 번호(§5.2.1, FR-A4, H0-a, Q1, MUST)와 기술 이름(JSON, REST, SSE, localStorage, SVG, OptaPlanner, 시드)은 **개발자 모드에서만** 보인다.
4. 한 개념에는 한 이름만 쓴다. 지금은 같은 뜻이 화면마다 다르게 불리는 곳이 있다(아래 ★ 표시).
5. 화면 글자만 바꾼다. 주소(`#step=1&tab=slots`)와 코드 이름은 그대로 둔다.

## 4. 적용할 때 주의할 점

- **화면 글자만 바꾼다.** `slots`, `slotIndexOfDate`, `data-act="draft-slots"`, 주소의 `tab=slots`·`view=slots`는 그대로 둔다. 이미 공유한 링크가 계속 열린다.
- **엑셀 시트 이름이 바뀐다.** 「슬롯」 → 「연전 기간」, 「이벤트」 → 「특별 경기」, 「휴식예외일」 → 「휴식일 경기」, 「경기없는기간」 → 「휴식기」. 이미 만든 파일도 계속 올라가도록 **예전 이름도 받아 준다.** 빈 양식과 배포 파일의 안내 시트도 함께 바꾼다.
- **자체 점검 코드**(`ui/app/studio/selftest.js`)가 「슬롯」 글자로 표의 줄을 찾는다(`tr[data-name="슬롯"]`). 함께 고친다.
- **같은 문구가 여러 파일에 흩어져 있다.** 「슬롯」만 해도 화면에 보이는 곳이 26개 파일, 130곳 남짓이다(`ui/core/score.js`의 규칙 이름, `ui/core/mock-solver.js`, 재생기, 소개 페이지 `ui/show/` 포함). 규칙 이름은 `score.js` 한 곳에서 바꾸면 ②③④에 함께 반영된다.
- **개발자 모드로 옮길 표기**는 이미 있는 개발자 모드 장치(`S.dev()`)를 쓴다.
- 「기간마다 5시리즈」, 「× 5」처럼 숫자가 들어간 문구는 지금 코드가 구단 수로 계산한다(`teams.length >> 1`). 바꿀 때도 숫자를 박아 넣지 말고 계산값을 쓴다.
- 「원정 vs 홈」 순서와 「특별 경기」는 담당자에게 한 번 확인받는 것이 좋다.

### 이번에 보지 못한 화면

- 버튼을 눌렀을 때만 뜨는 알림(토스트)과 입력 오류 문구 대부분. 코드에서 찾아 같은 규칙으로 바꾼다.
- ② 자동 편성이 돌아가는 동안과 끝난 뒤의 진행 표시
- 시즌 운영 › 재편성 실행 뒤의 결과 화면
- 개발자 모드를 켠 화면 (그대로 둘 곳이라 검토에서 뺐다)

2. 「이벤트」의 새 이름: **특별 경기**(추천) / 지정 경기 / 그대로
3. 대진 표기: **롯데 vs LG (오른쪽 홈)**(추천) / 롯데–LG / 그대로 `@`
4. 「필수 규칙」과 「꼭 지킬 규칙」 중 하나로 통일
5. 개발자 표기(§, FR, JSON, REST 등): **개발자 모드로 숨김**(추천) / 삭제
6. 적용 순서: 한 번에 전부 / 단계별로(① → ② → ③ → ④ → 시즌 운영)
