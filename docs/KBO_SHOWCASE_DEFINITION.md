# 보여주는 문 — 정의서 (v0.1, 2026-10-20)

> [제품 정의서](KBO_PLAYGROUND_PRODUCT_DEFINITION.md) §2의 "보여주는 문"(팬·모바일)을 정한다. 만져보는 문(`ui/` 위저드)과 재생기(`ui/replay.html`)는 이미 main에 있다.
> 목표: 홍보 글에서 휴대폰으로 들어온 사람이 **3분 안에** "컴퓨터가 KBO 일정을 더 공평하게 짠다"를 보고, **한 번 돌려 보고**, **링크로 퍼 나른다**.

## 1. 비교에 쓸 숫자 (2026-10-20 측정)

실제 일정 = `input_2025.json`의 1차 편성(3/22~8/29, 45슬롯 225시리즈, KBO 발표 일정). 엔진 = 서버 멀티스타트(8시드·10초·시드 42·새로 짜기). 둘 다 같은 채점기(브라우저 JS = Java 엔진, 점수 일치 확인)로 쟀다.

| 지표 (일반 용어) | 실제 2025 1차 일정 | 엔진 (10초) | 비고 |
| :--- | :--- | :--- | :--- |
| 10구단 총 이동거리 | **72,955 km** | **62,728 km** | 14% 적음 |
| 구단 간 이동거리 차이 (최다 − 최소) | 1,372 km (KIA 8,084 / 두산 6,711) | 467 km (롯데 6,557 / 두산 6,090) | 엔진이 훨씬 고름 |
| 구단별 이동 횟수 | 32~38회 | 31~34회 | |
| 휴일 가중치 (주말·공휴일 홈의 무게) | 22~28 | 24~26 | 엔진이 고름 |
| 주말 홈 시리즈 수 | 11~12 | 10~13 | **실제 일정이 더 고름** |
| 가장 긴 원정 연속 | 2~3시리즈 | 3시리즈 | 비슷 |

솔직하게 적을 것: 엔진은 **이동거리와 그 공평성**을 목표로 두었고, 주말 홈 수는 직접 목표가 아니라 실제 일정보다 못하다. 실제 일정은 엔진이 모르는 조건(구장 대관·공사, 중계, 지역 행사, 구단 요청)을 반영한다. 이 차이를 숨기지 않는 것이 KBO와 전공자에게 신뢰를 준다.

헤드라인 후보: **"같은 조건, 10초 만에 이동거리 14% 절감·구단 간 편차 1/3"**.

## 2. 페이지 구성 (모바일 우선, 3쪽)

### 2.1 `/` 소개
| 순서 | 블록 | 내용 |
| :--- | :--- | :--- |
| 1 | 한 문장 + 숫자 3개 | "KBO 144경기 일정, 컴퓨터가 10초 만에 짜면?" 아래 총 이동거리·구단 간 차이·걸린 시간 |
| 2 | 비교 카드 | 실제 vs 엔진 가로 막대 2개(총 이동거리), 구단별 작은 막대 10개. "자세히" → `/compare` |
| 3 | 탐색 과정 미리보기 | 재생기(`replay.html` 모바일 레이아웃)를 iframe이 아닌 같은 모듈로 넣어 15초 자동 재생. 탭하면 전체 재생 |
| 4 | 직접 해보기 | 모바일: 손잡이 2개(이동거리 허용오차, 어린이날 홈 구단)만 두고 「편성 시작」→ 10초 진행 → `/r/<id>`. PC: 위저드로 |
| 5 | 어떻게 하는 건가요 | 3문단: 조합최적화가 뭔지(간호사 배정·배송 경로와 같은 문제), 제약과 목표, 메타휴리스틱이 해를 고쳐 가는 방식(재생기가 그것). 산업공학 소개 한 줄 |
| 6 | 만든 사람 | 이름·한 줄 소개·이전 글(mlbpark 비교 글) 링크·연락처 |
| 7 | 공유 | 링크 복사, X·스레드·카카오톡 공유 |

### 2.2 `/compare` 실제 vs 엔진
§1 표 전체 + 구단별 막대 차트(이동거리·주말 홈) + "엔진이 모르는 것" 목록 + 방법(제약·목표·채점기 동일) + 데이터 출처. 데스크톱 위저드의 ④ 지표와 같은 숫자를 쓴다.

### 2.3 `/r/<id>` 결과 공유
제목("이동거리 허용오차 200km·어린이날 홈 두산·키움·한화·NC·롯데"처럼 조건 요약), 숫자 3개(실제 대비), 재생기(모바일 세로), 조건 표, 「나도 해보기」, OG 메타. 데스크톱에서 열면 「위저드에서 이어서 다듬기」 버튼으로 같은 조건·시드를 위저드에 싣는다.

## 3. 공유 링크
- `id` = 서버 캐시 키(문제+옵션 SHA-256)의 앞 12자리. 같은 조건·시드면 같은 id, 재현 가능(엔진 REPRODUCIBLE).
- 서버는 `done` 결과를 **디스크**(`data/results/<id>.json`, plan·score·seedResults·trace·옵션·입력 해시)에 남긴다. 재시작해도 링크가 산다. 메모리 LRU는 그대로 두고 디스크를 뒤에 둔다.
- `/r/<id>`를 열었는데 파일이 없으면(오래된 링크·다른 서버) 조건이 URL 쿼리에도 있으므로 10초 재계산 후 보여 준다. URL: `/r/<id>?p=<base64 조건>&seed=<n>`.
- 만료·삭제 정책: 디스크 상한(예: 20,000건·2GB)에 닿으면 오래된 것부터 지운다. 소개 페이지의 기본 결과(`/r/default`)는 지우지 않는다.

## 4. OG 이미지
- `GET /og/<id>.png` 1200×630. Java `java.awt`(헤드리스)로 그린다. 외부 의존성 없음. 내용: 제목 한 줄, 숫자 3개(큰 글자), 실제 vs 엔진 막대 2개, 하단 사이트 이름. 한글 폰트는 VM에 Noto Sans KR 설치(없으면 기본 폰트로 떨어지되 깨지지 않게).
- 소개·비교 페이지는 고정 이미지(`/og/default.png`, 같은 코드로 생성해 커밋).
- 캐시: 파일로 저장, Cloudflare가 캐시.

## 5. 구현 위치와 규칙
- 정적: `ui/show/`(index.html, compare.html, r.html, show.css, show.js). 빌드 없음, 디자인 토큰은 `ui/app/common/common.css` 재사용, 모바일 375px 우선·데스크톱은 가운데 720px. 재생기는 `ui/app/replay/` 모듈 재사용(모바일 레이아웃 다듬기).
- 서버 라우트 추가: `/`→`ui/show/index.html`(위저드는 `/studio/`로 옮김), `/r/<id>`→r.html, `/api/v1/results/<id>`, `/og/<id>.png`, `/api/v1/compare`(실제 일정 채점 결과, 서버 시작 때 한 번 계산).
- 기본 결과: 서버 시작 시 `data/results/default.json`이 없으면 기본 조건(시드 42·10시드·30초)으로 한 번 만든다. 소개 페이지의 숫자·재생은 이 파일을 쓴다.
- 분석·피드백: Cloudflare Web Analytics(쿠키 배너 불필요) + 구글 폼 링크. 이벤트 3개만 센다: 편성 시작, 결과 공유 클릭, 위저드 진입.
- 모바일 성능: 소개 페이지 첫 화면은 JS 없이 숫자가 보이고(서버가 HTML에 숫자를 박아 넣거나 정적 JSON), 재생기는 뷰포트에 들어올 때 로드.
