# 결과 고치기 — 측정과 실제 엔진 실험 (2026-11-07)

> 엔진 결과를 사람이 고치는 방법을 정하면서 잰 숫자와 실제 엔진 실험. 이 기록을 근거로 「결과 고치기」(2027 「일정 자세히 보기」 맨 위 시즌 띠, `ui/app/studio/plan-edit.js` · `ui/core/fix-plan.js`, 병합 7586bc4)를 만들었다.
> 바탕 일정은 모두 기본 제공 2027 1순위 결과(`ui/data/plans/2027-rank1.json`, 필수 규칙 위반 0, 3분 동안 10번 시도해 만든 것). 재현 스크립트는 [experiments/result-edit/](experiments/result-edit/).

## 1. 결론

- 기존 「손으로 옮기기」는 사실상 쓸 수 없었다: 경기 하나만 옮기면 규칙을 지키는 경우가 0, 두 경기 맞바꾸기는 22,575가지 중 24가지.
- 그래서 결과 고치기를 **연전 고정 + 홈 지정 + 손으로 놓기 → 「검사하고 저장」 또는 「나머지 엔진으로 짜기」**로 정했다(사용자 결정).
- 실제 엔진에서 「처음부터 다시 짜기(고정 유지)」는 8가지 상황 중 7가지를 위반 0으로 풀었고, 고정한 경기는 한 번도 움직이지 않았다. 「이어서 풀기」는 홈 지정만 넣으면 아무것도 바꾸지 못했다.
- 그래서 「나머지 엔진으로 짜기」와 홈 지정이 바뀐 뒤의 운영 방침 실행은 **처음부터(60초)**, 서버가 시작을 못 하면 **이어서 풀기로 자동 전환**한다.
- 대가: 바꿔도 되는 경기는 90% 넘게 바뀌고 전체 이동 거리가 늘어난다. 시즌 끝 무렵(연전 4개 남음)은 실패한다.

## 2. 손으로 옮기기가 왜 안 되나 (브라우저 채점기로 전수 측정)

연전 기간마다 10구단이 모두 한 경기씩 한다(2027: 연전 45개 = 2연전 1 · 3연전 43 · 4연전 1, 경기 225개, 개막전 고정 5개).

| 방법 | 가능한 경우 | 필수 규칙 위반 0 | 비고 |
| :--- | ---: | ---: | :--- |
| 경기 하나를 다른 연전으로 옮기기 | 9,030 | **0** | 옮긴 두 구단이 그 연전에 두 경기가 된다 |
| 두 경기 맞바꾸기(같은 대진끼리 제외) | 22,575 | **24** | 23개는 결과가 나빠지고 1개는 그대로. 옮길 곳이 있는 경기는 220개 중 38개 |
| 함께 옮기기(겹치는 구단을 따라 묶어 두 연전 사이에서 통째로) | 8,688 | 348 | 옮길 곳이 있는 경기 162개. 엔진의 Kempe 이동과 같은 원리. 1순위에서는 모두 결과가 나빠짐 |
| 홈·원정 바꾸기 | 225 | 75 | 구단별 홈 경기 수(69/66)가 깨져 제외 |

연전을 비우고 그 경기들만 다시 나눠 넣는 경우(붙어 있는 3연전, 원래 일정 포함한 규칙 준수 배치 수):

| 비운 연전 | 나누는 방법 | 규칙을 지키는 배치 |
| :--- | ---: | ---: |
| 2개 | 2~4 | 거의 원래 일정 1개 |
| 3개 | 6~48 | 1~6 |
| 4개 | 96~1,536 | 1~10 |

스크립트: `count-simple-moves.js`, `count-chain-moves.js`, `count-refill.js` (`node <스크립트> <저장소 경로>`).

## 3. 실제 엔진 실험

방법: 1순위 결과에 연전 고정(그 연전 경기 모두 고정) · 홈 지정(이벤트 `mode: 'STADIUM'`, `fix: 'home'`) · 손으로 놓기(옮기고 그 경기만 고정)를 넣은 문제 8개를 `JobManager.submit`으로 풀었다. 30초, 무개선 15초, 시도 4가지(운영 서버와 같은 수), 처음부터(SCRATCH)와 이어서(KEEP) 각각. 전체 출력: `experiments/result-edit/results-2026-11-07.txt`.

### 알게 된 것

1. **고정·홈 지정은 확실히 지켜진다.** 모든 실행에서 고정한 경기는 하나도 움직이지 않았다.
2. **이어서 풀기는 새 홈 지정만으로는 한 걸음도 못 뗀다**(①⑤⑥, 15초 무개선으로 멈춤, 4가지 시도 모두). 엔진 이동(`SeriesReassignmentMove.isMoveDoable` → `RoundNeighborhood.preserves`)은 모든 구단 출전·구장 겹침·같은 대진 연속·4연속을 깨는 이동을 점수 전에 버린다. 지정을 맞추려면 중간에 규칙을 깨야 하는 길뿐인 것으로 보인다. 손으로 옮겨 이미 위반이 많은 상태(②③)에서는 이어서 풀기가 지정까지 맞췄다. **30초 넘게 돌려 본 적은 없다**(시간을 늘리면 되는지는 확인하지 않음).
3. **처음부터 다시 짜기는 바꿔도 되는 경기의 90% 이상을 바꾼다.** 전체 이동 거리 +6~15%(30초 실험, 바탕은 3분 결과라 실행 시간 차이도 섞여 있음).
4. **시즌 끝 무렵은 위험하다.** 연전 10개가 남으면 위반 0이지만 주말·공휴일 격차가 허용을 크게 넘고, 4개가 남으면 처음부터는 시작을 못 한다.
5. **「처음부터 짤 수 없음」은 일정이 없다는 증명이 아니다.** 첫 일정 만들기(`BaseballSolutionInitializer`)는 횟수 한도 안에서만 찾는다: 시작마다 40번 시도(`ATTEMPTS_PER_START`), 탐색 노드 한도 4,000 / 20,000 / 50,000. 이 값들은 2026-10-18 생성기를 처음 만들 때(08d6c53) 정해졌고 근거 기록이 없으며, 사용자 고정을 지키는 기능(40a6b4b, 2026-10-30)보다 먼저라 고정이 많을 때를 고려한 값이 아니다. 한도를 늘리는 실험은 하지 않았다.
6. **고정된 경기가 하나라도 있는 연전은 엔진의 다듬기(Kempe·연전 묶음 이동) 대상에서 통째로 빠진다**(`RoundNeighborhood`의 `movable`). 그래서 손으로 놓은 경기가 있는 연전의 나머지 경기는 처음 짤 때만 정해지고 그 뒤로 다듬어지지 않는다.
7. **실행 전 검사는 고정한 것만 남겨 채점하면 거짓 위반이 나온다**(예: 「KIA 홈 4연속 4/23~6/29」 — 사이의 빈 연전을 건너뜀). 그래서 `fix-plan.js`의 실행 전 검사는 비어 있으면 당연히 걸리는 규칙(모든 구단 출전·구장 수·시리즈 수)을 빼고, 4연속·같은 대진 연속은 실제로 붙어 있는 고정 연전 사이에서만 본다.

## 4. 실제 서버로 한 시험 (시즌 띠, 병합 전)

`scripts/run-server.sh`(4코어 제한, 시도 4가지)로 띄우고 스튜디오에서 직접 눌렀다.

| 상황 | 결과 |
| :--- | :--- |
| 3·4·7월 고정 + 6/1 롯데 홈 + 손으로 1경기 | 처음부터, 39초(30초 무개선으로 멈춤), 위반 0, 고정 경기 91개 그대로, 롯데 홈 지킴. 주말·공휴일 격차 3→4로 「허용 3점 넘음」 표시. 버전 자동 저장 |
| 8/20까지 고정 + 8/27 SSG 홈 | 실행 전 「새로 짤 연전이 4개뿐」 경고. 서버가 처음부터를 거절 → 화면이 이어서 풀기로 자동 재전송 → 위반 1건(두산·KT 같은 대진 연속) 남음, 저장하지 않음, 고정 경기 205개 그대로 |

시험하지 못한 것: 이어서 풀기마저 실패하는 경우(「고정한 연전이 많아 새로 짤 수 없습니다」).

## 5. 이 기록으로 정한 것 (사용자 결정 2026-11-07)

- 고정은 연전 기간 단위만. 손으로 놓은 경기는 그 경기만 고정. 고정한 연전으로 넣거나 빼는 것은 막음.
- 「검사하고 저장」: 위반이 있으면 버전 저장·확정을 막음(작업 중 자동 보관은 유지).
- 「나머지 엔진으로 짜기」: 실행 전 검사(고정한 것끼리의 위반)는 막음, 새로 짤 연전이 적으면 경고만, 처음부터 60초, 못 열면 이어서 풀기.
- 홈 지정(개막전·어린이날 포함)이 바뀌면 운영 방침 실행도 처음부터. 고정·손으로 놓은 경기는 운영 방침 실행에서도 지킴.

```bash
# 문제 만들기(바탕 일정 + 고정·지정·손으로 놓기 8가지)

# 실제 엔진으로 풀기: EditFlowExperimentTest.java.txt를 src/test/java/org/optaplanner/examples/baseball/web/EditFlowExperimentTest.java로 복사한 뒤

# 정리
node docs/experiments/result-edit/analyze.js "$PWD" target/edit-exp
```

실험 시험 파일은 `mvn test`가 매번 돌리지 않도록 저장소에 시험으로 두지 않고 `.txt`로 둔다. 8가지 × 2방식 × 30초라 10분쯤 걸린다.
