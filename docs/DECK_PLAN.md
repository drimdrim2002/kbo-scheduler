# 매치봇 발표 자료 구성 계획서

발표 자료를 만들 때 따르는 계획이다. 근거는 조사 보고서 `reports/KBO 일정 편성 발표 구성 관행.md`이고, 결정은 사용자가 2026-11-08에 정했다.

## 1. 목적과 원칙

- **목적:** 발표자의 이름을 알리는 것(명성)이다. 개인 프로젝트이므로 영업이나 투자 발표가 아니다.
- **주인공은 도구다.** 매치봇은 편성 담당자가 조건을 넣고 바꿔 가며 일정을 직접 만들어 보는(시뮬레이션하는) 스튜디오다.
  - 운영 방침에 따라 여러 번 편성하고, 결과를 비교하고, 고치고, 확정한다.
  - 2025 일정을 다시 짠 결과는 이 스튜디오로 해 본 **예시 하나**일 뿐이다.
- **넣지 않는 것**
  - 재무 관점: 가격, 매출, ROI, 비용 절감, 사업 모델, 투자.
  - KBO가 지금 일정을 짜는 방식(기사 내용 포함). 정확히 모르기 때문이다.
  - MLBPARK 글(추천 수, 주소).
  - 아직 없는 기능은 화면에 보이지 않는다. 말할 때는 「지원 예정」으로만 말한다.
- **말투:** KBO의 일정을 깎아내리지 않는다. 도구를 보여 주고, 판단은 청중에게 맡긴다.
- **슬라이드 규칙**
  - 한 장에 주장 하나만 담는다.
  - 제목은 결론을 담은 한 문장(두 줄 이내)으로 쓰고, 그 아래에 그림이나 화면으로 근거를 보인다.
  - 글머리표 목록과 개발 용어는 쓰지 않는다.

## 2. 핵심 메시지와 숫자의 자리

**핵심 메시지:** 「편성 담당자가 조건을 넣고 바꿔 가며, 규칙을 모두 지키는 일정을 몇 분 만에 여러 개 만들어 보고 고를 수 있습니다.」

**숫자는 전면에 내세우지 않는다.** 결과를 믿을 수 있는지 묻는 대목(4장 E)에서 근거 하나로만 쓴다. 이유는 매치봇이 받은 입력(대진, 규칙, 거리)이 KBO가 실제로 쓰는 입력과 다르기 때문이다. 그래서 숫자는 우열 비교가 아니라 「같은 잣대로 재면 이 정도 일정이 나온다」는 참고로 쓴다.

| 같은 잣대로 잰 참고 숫자 | 실제 2025 일정 (KBO 발표 1차) | 매치봇 예시 결과 |
| :--- | :--- | :--- |
| 필수 규칙 위반 | — | 0건 |
| 구단 간 이동 격차 | 1,603km | 716km |
| 10개 구단 총 이동거리 | 71,213km | 61,803km |

- **범위:** 2025-03-22 ~ 08-29, 225시리즈, 45개 연전 묶음.
- **출처:** `ui/show/fixtures/compare.json`, `data/results/default.json`. `default.json`은 소개 쪽 숫자의 원본이므로 다시 만들지 않는다.
- 이 숫자를 보일 때는 「입력이 실제와 다르다」를 같은 장에 적는다.

## 3. 만나는 순서

1. **KBO 관계자** (먼저)
2. **업계 행사**
3. **언론**: 새 소재는 **2027 일정 만들기**다.

언론에 줄 2027 결과는 언론에 내기 전까지 커뮤니티에 올리지 않는다.

## 4. 15분 본편 (모든 판의 뼈대)

앞부분(A·B)과 끝부분(H)은 모든 판에서 같다. 가운데 묶음을 넣고 빼서 길이를 맞춘다.

| 묶음 | 시간 | 장수 | 슬라이드 제목 (결론 문장) | 근거 그림 |
| :--- | :--- | :--- | :--- | :--- |
| A. 아는 장면 | 1분 | 1 | 「일정의 조건은 서로 얽혀 있어서, 하나를 바꾸면 시즌 전체가 달라집니다」 | 어린이날 홈 하나를 바꿨을 때 달라지는 이동·휴식 그림 |
| B. 결론과 소개 | 1분 | 2 | 「조건을 넣고 바꿔 가며 일정을 직접 만들어 보는 도구를 만들었습니다」 / 발표자 15초 소개 | 스튜디오 첫 화면 |
| C. 누가 무엇을 정하나 | 2분 | 2 | 「사실과 지정과 방침은 사람이 정하고, 나머지 배치는 자동 편성이 합니다」 | 역할 나눔 그림(매뉴얼 2장의 사실·지정·방침) |
| D. 한 번 따라가 보기 (녹화) | 5분 | 4 | 「조건을 넣으면」 → 「방침마다 일정이 나오고」 → 「나란히 비교하고」 → 「손대면 나머지를 다시 맞춥니다」 | 녹화 영상 4토막: 편성 조건 → 운영 방침 두 개로 실행 → 실행 결과 비교 → 결과 고치기·확정 |
| E. 믿을 수 있나 | 2분 | 2 | 「어떤 일정이든 필수 규칙을 하나하나 점검합니다」 / 「같은 잣대로 재면 이 정도 일정이 나옵니다」 | 요구 사항 점검표, 2장의 참고 숫자(입력이 다르다는 주석과 함께) |
| F. 아직 모르는 것 | 1분 | 1 | 「도구가 모르는 조건은 사람이 알려 줘야 합니다」 | 반영하지 못한 조건 목록(구장 사정, 중계 등). 특정 날짜 홈 불가와 시즌 중 다시 짜기는 지원 예정 |
| G. 방법 한 장 | 1분 | 1 | 「먼저 규칙을 모두 지키는 일정을 만들고, 여러 번 다듬어 가장 나은 것을 고릅니다」 | 탐색 과정 재생 장면 |
| H. 초대 | 1분 | 1 | 「schedulelab.kr에서 직접 짜 보세요」 | 사이트 주소, QR, 연락처 |
| 여유 | 1분 | | | |
| 합계 | 15분 | 14 | | |

- **자기소개(B):** 15초. SCM·물류 조합최적화 엔지니어이고 개인 프로젝트로 만들었다는 것만 말한다.
- **녹화(D):** 2027 데이터로 찍는다. 결과 고치기 장면을 넣는 근거는 결과를 조금이라도 고칠 수 있으면 사람들이 자동 결과를 더 받아들인다는 연구(Dietvorst 2018)다.

## 5. 판별 구성

### KBO 관계자판: 회의 1시간 = 발표 약 15분 + 녹화 시연 10분 + 토의 35분

(앞서 정한 「발표 25분, 시연 10분 포함」과 같은 배분이다.)

D가 이 판의 중심이다. 본편 D(5분)를 빼고, 발표 뒤 토의 바로 앞에 녹화 시연 10분을 둔다.

**C를 늘린다(+3분).** 운영자가 정하는 것을 KBO의 언어로 하나씩 보인다.
- 사실: 구단, 구장, 시즌 기간, 주요 이벤트 일정.
- 지정: 개막 2연전 홈, 어린이날 홈, 특정 연전 고정.
- 방침: 이동 격차를 줄일지, 주말·공휴일 격차를 줄일지, 그리고 허용 수준.

**녹화 시연 10분의 시나리오**
1. 2027 편성 조건 입력·검증
2. 운영 방침 두 개를 실행
3. 실행 결과 비교: 「여기서 갈림」으로 두 일정이 처음 달라지는 곳을 보인다.
4. 현재 결과 분석: 요구 사항 점검표를 보인다.
5. 결과 고치기에서 연전을 고정하거나 홈을 지정한 뒤, 「나머지 자동 편성」을 실행한다.
6. 확정

**마지막 요청:** 결정이 아니라 확인을 부탁한다.
- 「KBO가 실제로 쓰는 조건을 한 번 넣어 보게 해 주세요.」
- 빠진 규칙을 알려 달라고 한다.
- 실무자가 직접 한 번 돌려 봐 달라고 한다.

**남기는 자료:** 1쪽 요약, 운영 매뉴얼 핵심판(24쪽), 사이트 주소.

**예비 슬라이드**(토의 때 꺼냄): 규칙 전체 표, 참고 숫자의 구단별 표, 거리 계산 방법, 실행 시간, 방침별 결과 차이.

### 업계 행사판: 20~30분

본편에 「만든 과정」 묶음(5~10분)을 더한다.
- 왜 만들었나.
- 규칙을 모두 지키는 일정을 만드는 데서 처음 막힌 이야기.
- 실행마다 결과가 크게 달라서, 여러 번 돌려 고르게 된 이야기.
- 비전문가가 쓰는 화면을 만들며 배운 것: 사실·지정·방침으로 나눈 이유, 「여기서 갈림」.

G(방법)는 조금 더 깊게 설명하되, 수식은 넣지 않는다. 마무리는 사이트 초대와 「함께 다듬을 사람을 찾습니다」다.

### 언론판: 7~10분 브리핑 + 1쪽 요약

순서는 A → B → D를 줄인 녹화 2분 → 2027 일정 만들기 결과 → H다.

**핵심 메시지 셋**
1. 편성 조건을 바꿔 가며 프로야구 일정을 직접 시뮬레이션하는 도구가 나왔다.
2. 누구나 schedulelab.kr에서 2027 일정을 짜 볼 수 있다.
3. 한 엔지니어가 개인 프로젝트로 만들었다.

참고 숫자는 기자가 물을 때만 꺼낸다. 이때 「입력이 실제와 다르다」를 함께 말한다.

**1쪽 요약의 순서**(국립국어원 보도자료 길잡이)
1. 표제
2. 부제(명사구 하나)
3. 주제문(육하원칙)
4. 본문(화면 한 장)
5. 만든 사람
6. 연락처
7. 그림 사용 안내(출처를 적으면 사용 가능)

**비슷한 사이트와 무엇이 다른가**(질문 대비 한 줄): 이동거리를 보여 주는 데서 그치지 않고, 조건을 넣어 일정을 직접 짠다.

## 6. 만드는 방법 (정할 것)

- **형식:** 정하지 않았다.
- **그림:** 스튜디오 화면 캡처를 쓴다. 매뉴얼 캡처(`docs/manual/img/`)를 다시 쓸 수 있는지 먼저 본다.
- **녹화 영상:** 2분짜리와 10분짜리 두 개를 만든다. 발표용 서버는 커밋된 코드로 띄우고, 녹화 중에는 다른 실행이 끼지 않게 한다.
