# opt-1 입력 분할형 — 표준과 다른 점

> 브랜치 `wizard-ui/opt-1` (`wizard-ui/std` 421e3de에서 분기) · 계획 "표준 1개 + 옵션 3개"의 opt-1 · 요구사항 §12.2
> **바뀐 곳은 ① 데이터 준비(모든 탭), 한 건 편집, 가져오기 미리보기뿐이다.** ②③④·시즌 운영·설정은 std와 같다. 그래서 "① 영역만 std 또는 opt-1"로 고를 수 있다.

## 무엇이 다른가

| 곳 | std 표준 | opt-1 입력 분할형 |
| :--- | :--- | :--- |
| ① 본문 | 시트 목록 · 시트 표 · 인스펙터(372px, 위쪽에 작은 입력 결과 그림) | 시트 목록 · **본문 좌우 분할**(왼쪽 시트 표 1.2 : 오른쪽 큰 그림 1) |
| 입력 결과 그림 | 인스펙터 위쪽. 행렬 칸 1440에서 약 30×30px, 1920에서 약 35×35px | 본문 오른쪽 칸 전체. 행렬 칸 1440에서 약 44×31px, 1920에서 약 64×39px(선택 없음 기준). 시즌 띠는 칸 안에 날짜 숫자를 쓰고 칸 높이를 화면에 맞춰 키운다. 1440처럼 낮은 화면에서는 연전 수급을 막대 대신 한 줄 칩(`3연전 시리즈 215 / 자리 215 ✓ 일치`)으로 줄여 행렬에 높이를 준다 |
| 행 인스펙터 | 늘 보임 | 선택이 없으면 **아예 없다**. 행을 고르면 생긴다: 1800 이상은 펼쳐서(360px) 밀려 나오고, 1440처럼 좁은 화면은 그림 크기를 지키려고 **30px 접힌 띠**(`행 인스펙터 · 시리즈 12행`)로 먼저 나온다. 띠의 `‹`로 펼치고(320px) `›`로 다시 접는다. 사용자가 한 번 펼치거나 접으면 그 선택을 따른다. 접어도 행 선택·그림 강조·삽입/삭제 버튼은 그대로다. `선택 해제` 또는 `Esc`로 선택을 풀면 사라진다. 이 상태는 ① 전용이라 ③의 인스펙터에는 영향이 없다 |
| 탭별 그림 | 같음 | 시리즈: 구단쌍 경기 수 행렬(바뀐 칸에 `이전→새 값`) + 연전 수급. 슬롯: 시즌 띠 + 연전 수급. 공휴일·휴식예외일·경기없는기간·이벤트: 시즌 띠 + **날짜 칩 목록**(누르면 그 행을 고른다). 시즌 골격: 규칙으로 만든 경기일 띠 + 규칙 미리보기(슬롯 수·연전 분포·초안 만들기) |
| 시즌 골격 왼쪽 | 폼 + 시즌 띠(3~10월) + 하위 시트 3칸 | 폼 + 하위 시트 칸. 시즌 띠는 오른쪽 큰 그림 하나로 합쳤다(같은 띠 두 개를 나란히 두지 않음) |
| 시트 표 | 열 너비 그대로 | 분할에 맞춰 열을 조금 줄이고, **검증 열을 오른쪽에 붙였다**(가로 스크롤해도 보임). 도구 막대는 좁으면 두 줄로 접힌다 |
| 구단과 거리 | 3분할 | 본문은 std와 같다. 인스펙터만 구단을 골랐을 때 연다 |
| 가져오기 미리보기 | 왼쪽 = 시트 표 + "가져온 뒤" 그림, 오른쪽 = 오류·경고 | 위 = 시트 표 │ 오류·경고, 아래 전체 폭 = **현재 ↔ 가져온 뒤 나란히**. 바뀌는 칸·슬롯·날짜를 양쪽 모두 파란 테두리로, 가져온 뒤 쪽 행렬은 `9→12!`처럼 이전 값을 함께 쓴다. 요약 줄: `바뀌는 칸 6 · 두 칸 합 ≠ 15: 현재 0쌍 → 가져온 뒤 3쌍`. 창은 std보다 크다(1440에서 1376×750, 1920에서 1600×920) |

그림 함수는 std의 `S.viz.ribbon / pairMatrix / balance / diffCounts / diffSlots / diffDates`를 그대로 쓰고 크기 인자만 더했다(`pairMatrix`: `left·top·fs·lfs·chgTip·chgLegend·arrow`, `ribbon`: `big·nums·chgLabel`). 인자를 주지 않으면 std와 똑같이 그린다. 배치는 `step-data.js`의 `S.inputViz`·`S.steps[1].render`, `import.js`의 `S.importViz`·`S.modals.import`에서 바꿨다. 그림 칸 크기는 그린 뒤 실제 크기를 재서 한 번 더 맞춘다(창 크기 변경 포함).

## 화면 주소 (opt-1에서 더한 인자)

| 화면 | 주소 | 비고 |
| :--- | :--- | :--- |
| ① 시즌 골격 | `step=1&tab=season` | 오른쪽: 규칙으로 만든 경기일 띠 + 규칙 미리보기 |
| ① 시리즈 (선택 없음) | `step=1&tab=series` | 인스펙터 없음, 큰 행렬 + 연전 수급 |
| ① 한 건 편집, 인스펙터 접힘 | `step=1&tab=series&demo=edit&rinsp=0` | 바뀐 칸 `9→12!`, 셀 오류 `LGG`, 오른쪽 끝 30px 띠 |
| ① 한 건 편집, 인스펙터 펼침 | `step=1&tab=series&demo=edit&rinsp=1` | 1440에서도 펼친 상태 |
| ① 슬롯 행 선택 | `step=1&tab=slots&row=8` | `row` = 시트 행 번호(머리글이 1행). 1440은 접힌 띠, 1920은 펼친 인스펙터 |
| ① 공휴일·예외일·경기없는기간·이벤트 | `tab=holidays&row=4`, `tab=restex`, `tab=blackouts&row=3`, `tab=events` | |
| ① 구단과 거리 | `step=1&tab=teams&row=4` | 인스펙터만 선택 시 열림 |
| 가져오기 미리보기 | `step=1&tab=slots&modal=import` | 시리즈 행렬 현재 ↔ 가져온 뒤 |
| 가져오기 미리보기 (시트 지정) | `...&modal=import&isheet=슬롯`, `isheet=공휴일` | `isheet`는 처음 고를 시트 |

- `rinsp=0`은 ① 행 인스펙터 접힘, `rinsp=1`은 펼침이다. 없으면 화면 폭으로 정한다(1800 이상 펼침). std의 `insp=0`(모든 단계 공통)과 다르다.
- 저장 키는 `kbo-wizard:opt-1:`(std와 겹치지 않음), 크롬 프로필은 `/private/tmp/claude-501/wizard-opt-1/`이다.

## 점검 결과

- **자가 점검**(`tools/studio/selftest.sh`, `?selftest=1`): 56개 모두 통과(1440×790, 1920×970). std 49개 중 ① 영역에 묶인 1개(`슬롯 선택 → 시즌 띠 강조`)는 그림 위치를 인스펙터(`.insp`)에서 본문 그림 칸(`.o1-viz`)으로 바꿨다. 새로 더한 7개:
  - 행 인스펙터 기본값: 행을 고르면 1800 이상은 펼침, 1800 미만은 접힌 띠(자가 점검이 화면 폭에 따라 확인)
  - 가져오기: 현재 ↔ 가져온 뒤 행렬이 나란히 있고, 바뀌는 칸이 양쪽에서 같은 수로 강조되며, 현재 쪽 값 = 현재 데이터, 가져온 뒤 값 ≠ 현재 값
  - 가져오기: 슬롯 띠 바뀐 칸 양쪽 강조, 공휴일 띠 가져온 뒤에 공휴일 1일 추가 + 그 날 강조
  - 행 인스펙터: 선택 전에는 없음(인스펙터·띠 모두 DOM에 없음) → 셀을 누르면 열리고 그림에서 그 구단쌍 강조
  - 행 인스펙터: 접기 → 30px 띠만, 선택·그림 강조·삭제 버튼 유지 → 펼치기 → `선택 해제`·`Esc`로 닫힘
  - ① 인스펙터 접기가 ③ 인스펙터에 영향 없음
  - 분할 그림: 슬롯 연전 3→2 편집 → 오른쪽 띠의 선택 칸 3→2, 바뀐 칸 강조·안내 → 실행 취소 → 복귀
  - (std 점검 `시리즈 셀 편집 → 행렬 칸 변경`도 이제 본문 오른쪽 행렬을 본다)
  - 일반 모드 금지어 검사의 ① 화면은 인스펙터를 펼친 상태로 검사한다(1440에서도 인스펙터 글이 검사되게).
- **페이지 스크롤**(`tools/studio/checkall.sh`, 경로 `tools/studio/routes.txt`): 37개 경로(opt-1 13개 + std의 다른 영역 24개) × 2크기(1440×790, 1920×970) = 74건 모두 페이지 스크롤 0, 콘솔 오류 0, 허용하지 않은 두 방향 스크롤 0이다.

## std와 비교한 장단점

| | 장점 | 단점 |
| :--- | :--- | :--- |
| 그림 크기 | 그림이 본문의 약 45%를 차지해 std보다 크다. 행렬 칸 면적이 1440에서 약 1.5배, 1920에서 약 2배다. 시즌 띠에 날짜 숫자가 들어간다. 1440에서 행을 골라도 인스펙터가 접힌 띠로 나와 큰 그림이 유지된다 | 1440에서 인스펙터를 펼치면 그림 폭이 std와 같아진다(행렬 칸 약 31×31px, 띠의 날짜 숫자는 숨김). 1440에서 연전 수급은 막대가 아니라 한 줄 칩이다 |
| 표 | 고친 셀과 바뀐 그림이 같은 높이에 나란히 있어 눈을 덜 옮긴다. 검증 열이 늘 보인다 | 표 폭이 std보다 좁다. 1440에서 시리즈 표의 `현재 배정`·`구단쌍 경기`·`메모` 열은 가로로 스크롤해야 보인다. 도구 막대가 두 줄이 되면 표가 한 줄 줄어든다 |
| 인스펙터 | 선택이 없을 때 화면이 넓다. 표에서 바로 고치면 인스펙터가 필요 없다. 접어도 선택과 강조가 남는다 | 1440에서는 인스펙터(값·검증·관련 정보)를 보려면 띠를 한 번 눌러야 한다. 1920에서는 행을 고를 때 오른쪽 칸이 생겨 본문 폭이 바뀐다(그림이 다시 그려짐). 시트 요약(행·오류·경고 수)은 그림 칸 머리의 배지로 줄었다 |
| 가져오기 | 현재와 가져온 뒤를 같은 크기로 나란히 보며 바뀌는 칸을 양쪽에서 찾는다. `9→12!`로 이전 값을 바로 읽는다 | 창이 화면을 거의 다 덮는다. 시트 목록·오류 칸 높이가 고정(286px)이라 오류가 많으면 오류 칸 안에서 스크롤한다 |
| 구현 | 그림 함수는 std 그대로(크기 인자만) | 그림 칸 크기를 어림한 뒤 실제 크기를 재서 한 번 더 그린다. 창 크기를 바꾸면 ①을 다시 그린다 |

## 알려진 빈틈

- 인스펙터가 펼쳐질 때 0.18초 밀려 나오며 본문 폭이 줄어 그림이 다시 그려진다(애니메이션은 닫힘→열림일 때만, `prefers-reduced-motion`이면 없음).
- 인스펙터 펼침·접힘 선택은 주소(`rinsp`)에만 남는다. 새로고침하면 주소의 값을 따른다.
- 창 크기를 바꾸면 ①을 다시 그린다. 셀 편집 중이면 입력 중인 값을 지킨다.
- 가져오기 "가져온 뒤" 그림은 std와 같이 xlsx·구글 시트에서는 미리 정한 목업 변경이다. 휴식예외일 시트는 변경이 없어 양쪽 띠가 같고 `변경 없음`으로 표시한다. 이벤트 추가 1건(3/3)은 1차 편성 기간 밖이라 양쪽 띠에 나타나지 않는다(요약 줄에 표시).
- std에서 이어받아 고친 것: ① 구단과 거리의 `다른 구장까지 거리`·거리 행렬 히트맵이 `distanceOf()`의 반환값(객체)을 숫자로 써서 `-`로 나오던 문제를 고쳤다. 같은 문제가 std `route-player.js` 57행에도 있다. 재편성 묶음 구간의 `leg`가 객체가 되어 `cum += leg`가 문자열이 된다(재편성 실행 후 이동 경로에서만 나타남). 이 파일은 opt-3 영역이라 opt-1에서는 고치지 않았다.

## 3. 일반 모드와 개발자 모드

- **설정 → 기능 탭 맨 위**에 `개발자 모드` 스위치가 있다. 값은 이 브라우저의 localStorage `kbo-wizard:std:dev`에 저장하고, 기본은 꺼짐이다. 주소에 `dev=1` 또는 `dev=0`을 붙이면 그 탭에서만 강제로 켜거나 끈다(스크린샷용).
- **일반 모드**: 개발자용 요소를 숨기는 데 그치지 않고 **DOM에 만들지 않는다**. 자가 점검이 50개 화면의 `textContent`와 `title`·`aria-label`을 검사해 금지어가 없음을 확인한다. 금지어는 `Hard`, `Soft`, `hard/`, `H0-`, `H1`, `S0`~`S4`, `RH-`/`RS-` 코드, `BendableLongScore`, `[-2/-1]` 같은 원점수 꼴이다.
- **개발자 모드**에서는 일반 용어 옆에 다음이 함께 보인다.
  - `필수 규칙 위반(Hard) 3건`
  - 규칙 코드 배지: `H0-b 한 구장에 두 경기`
  - 상단 원점수 `[-2/-1]hard/…soft`
  - Δ 수치: `Hard +1 해소 · Soft +489,287`
  - ② 개발자 옵션: 최대 시간, 개선 없음 종료, 시드, 초기해, 개선 횟수, Hard/Soft 현재 최고, 원점수, 점수 추이 차트
  - ④ 공정성 점수 구성의 공식과 원점수
- 코어·공통 모듈이 만든 문장에는 코드가 들어 있다. 예: 사전 점검 `미배정(S0)이나 …`, `H0-d 위반 유지`. 이런 문장은 `S.plain()`이 일반 용어로 바꾼다. 패널 제목·설명(`S.paneHead`)과 토스트(`S.toast`)는 모두 이 함수를 거친다.

| .xlsx 업로드·구글 시트 읽기 | 미리 준비한 미리보기를 띄운다(오류 2건). "가져온 뒤" 시각화도 미리 정한 변경으로 그린다(`S.importAfter`). 슬롯 2개, 시리즈 3행 변경, 1행 추가, 1행 삭제, 공휴일 6/3을 반영한다 |
| 편성 실행 | 정해 둔 진행률을 약 6초에 재생한다. **실행 시간 프리셋과 상관없이** 재생 시간은 같고, 표시되는 경과 시간만 프리셋을 따른다. 배정은 바꾸지 않는다 |
| 재편성 탐색 | 대상 계산과 탐색은 실제 코어를 쓴다. 실행 시간만 연출이다 |
| .xlsx 내보내기·빈 양식, REST 엔진·Kakao | 토스트로 알리거나 설정 값만 저장한다 |

다음은 목업이 아니다. 규칙으로 초안 만들기, 구단쌍 규칙으로 만들기, 입력 결과 시각화, 이동 경로 재생은 실제 데이터로 계산한다.

## 10. 점검 결과

- **페이지 스크롤**(`tools/studio/checkall.sh`, 경로 `tools/studio/routes.txt`): 32개 경로 × 2크기(1440×790, 1920×970) = 64건이다. 모두 페이지 스크롤 0, 콘솔 오류 0, 허용하지 않은 두 방향 스크롤 0이다.

  - 편성 중에는 옵션 대신 진행 막대·경과 시간·상태 문장만 보임
  - 일반 모드에 개발자 옵션 없음
  - 실행 시간 프리셋 → `timeLimitSec`(300·1800), 시작 방식 → `init`
  - 개발자 모드 켜기(Hard/Soft·원점수·개발자 옵션·점수 추이) → localStorage 저장 → 끄기(사라짐)
  - 시리즈 셀 편집 → 행렬 칸 값 변경, 바뀐 칸 2개 강조, 합 ≠ 15 표시 → 실행 취소 → 복귀
  - 슬롯 선택 → 시즌 띠 강조
  - 가져오기 미리보기 시각화(시리즈 행렬, 슬롯 띠)
  - 지표 차트 클릭 → 표·막대·점 3줄 모두 같은 구단 강조, 키보드 Enter 선택
  - 이동 경로 재생 → 정지 → 타임라인 칸으로 위치 이동 → A6 끄면 탭 제거
  - **일반 모드 금지어 검사**: 50개 화면에서 금지어가 없어야 한다. 대상은 ① 시트 8개·한 건 편집, 가져오기 3종의 시트별 미리보기, 구글 시트, ② 일반·차단·편성 중, ③ 위반별·시리즈·빈 인스펙터·슬롯 목록·구단×슬롯·스냅샷 메뉴·데이터 메뉴, ④ 보기 13개와 공정성 단계 5개, 시즌 운영 3탭과 재편성 묶음, 설정 3탭이다. 선택 기능은 모두 켠다.
  - 검사기 자체 확인: 개발자 모드에서는 같은 검사가 코드를 잡아야 한다
- 1800px·900px 구간이 바뀌면 다시 그린다(창 크기 변경 대응). 그래서 1920 스크린샷의 차트·달력도 970 높이 기준으로 그려진다.

## 12. 알려진 빈틈

- 편성 실행은 목업이라 실행 시간 프리셋이 실제 탐색 시간을 바꾸지 않는다. `timeLimitSec`·`unimprovedSec` 값만 바뀐다.
- 가져오기 미리보기의 "가져온 뒤" 그림은 xlsx·구글 시트에서는 미리 정한 변경이다. 보조 생성 두 가지만 실제 생성 결과다.
- ① 구단과 거리 탭에는 입력 결과 그림을 더하지 않았다. 본문에 이미 지도와 히트맵이 있다.
- 이동 경로의 재편성 구간은 시즌 운영에서 재편성을 실행한 뒤에만 나온다. 묶음마다 첫 경기 날짜로 한 구간을 만든다. Kakao 지도 모드는 지원하지 않는다(내장 SVG만 쓴다).
- 점 차트에서 같은 값에 구단이 몰리면 이름이 위아래 여러 줄로 쌓여 옆 줄과 가까워진다. 1440×790의 이동 횟수·주말 홈 줄이 그렇다.
- ④ 상대 매트릭스(A5)와 거리 히트맵은 alt-a의 공통 `KBO.Chart.heatmap`을 그대로 쓴다. 중간 단계 칸의 흰 글자 대비가 AA(4.5:1)에 못 미칠 수 있다. 새로 만든 ① 구단쌍 행렬은 6~8 칸에 남색 글자를 써서 4.9:1을 맞췄다.
- 일반 모드 검사는 화면에 그려진 DOM만 본다. 토스트는 자가 점검 중 끄므로 `S.toast`의 `S.plain` 변환으로만 막는다.
- alt-a에서 이어받은 빈틈: 드래그 중 Δ 미표시, 가져오기 배정 초기화는 확인만 받음, 새로고침하면 시연 초기 상태로 돌아감.
