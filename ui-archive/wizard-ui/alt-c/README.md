# alt-c 편성 워크북 (Scheduling Workbook)

> 브랜치 `wizard-ui/alt-c` · 요구사항 `KBO_WIZARD_UI_REQUIREMENTS.md` §8 alt-c · 진입점 `index.html` (file://로 바로 열림)

## 콘셉트

엑셀로 일하는 운영팀을 위한 **시트 격자 중심** 시안이다. 상단 가로 스테퍼(① 데이터 준비 ② 검토·실행 ③ 결과·수정 ④ 품질·배포)가 큰 흐름을 잡는다. 단계 안에는 언제나 같은 다섯 부품이 같은 자리에 있다.

1. **명령 띠**: 그 단계의 동작만 둔다. 리본이 아니라 한 줄짜리다.
2. **수식 줄**: 이름 상자(`시리즈!B12`), 선택 셀의 값과 열 정보, 검증 메시지를 보여 준다.
3. **큰 격자**: 열 문자·행 번호, 고정 머리글, 녹색 선택 테두리가 있다.
4. **시트 탭**: 가져오기 시트 6종과 **1:1**로 대응한다.
5. **오른쪽 작업 창**: 검증·미리보기·상세를 담는다.

가져온 `.xlsx`의 행 번호와 화면의 행 번호가 같다. 그래서 `시리즈 12행 B열(원정)` 같은 오류 주소를 그대로 따라갈 수 있다.

결과 단계도 격자 문법을 쓴다. 일정은 슬롯 × 경기 격자이고, 같은 탭에서 월간 달력으로 바꿔 볼 수 있다. 구단 × 슬롯 매트릭스는 켜고 끌 수 있다. 분석 단계는 조건부 서식이 들어간 지표 시트에 **차트 개체**를 얹고, 큰 차트는 **차트 시트**로 따로 둔다.

## 실행

```bash
open index.html                     # 그대로 열기 (라이브러리·웹 폰트·네트워크 없음)
open "index.html?debug=scroll"      # 오른쪽 아래에 페이지 스크롤 점검 표시
open "index.html?reset=1"           # 이 시안의 localStorage(기능 켜기·끄기, 구글 시트 URL) 초기화
```

- 시안은 매번 같은 상태에서 시작한다. 작업 상태는 자동 저장하지 않는다.
- 2025 프리셋에 **가상 위반 3건**을 얹었다. 기능 켜기·끄기 상태만 `localStorage`(`kbo-wizard-alt-c:features`)에 저장한다.

## 화면 상호작용 (실제로 동작함)

- **단계·시트 이동**: 단계 탭, 시트 탭, 이전/다음 버튼(다음 버튼에 현재 단계 상태 표시)으로 오간다. 사전 점검 링크와 위반 클릭은 해당 단계·시트·셀로 이동한다.
- **격자**
  - 방향키, Ctrl+방향키, Home/End, PageUp/Down, Tab으로 이동한다.
  - Enter·F2·글자 입력으로 편집을 시작하고, Enter·Tab으로 확정, Esc로 취소한다.
  - Delete는 셀을 지운다. Shift+F10이나 오른쪽 클릭은 행 메뉴(위·아래 삽입, 행 삭제, 셀 편집·지우기)를 연다.
  - 입력하는 동안 오류 메모 풍선과 수식 줄 메시지가 바로 바뀐다. 오류 값도 확정할 수 있고, 확정하면 셀에 빨간 모서리 표식이 남는다(Google Sheets의 "경고 표시" 방식).
- **실행 취소**: 셀 편집, 행 삽입·삭제, 가져오기 적용, 시리즈 교환, 핀, 스냅샷 복원, 경기 기록, 재편성을 되돌릴 수 있다. Ctrl+Z·Ctrl+Y와 명령 띠 버튼을 쓴다. 기록은 워크북 시트 모델과 저장소(Store) 두 곳에 걸쳐 하나로 묶었다.
- **가져오기 미리보기**
  - 시트마다 행 수와 +/~/− 건수를 보여 주고, 오류 2건(`시리즈 12행 B열(원정): 알 수 없는 구단 'LGG' — 'LG'인가요?`, `이벤트 8행 C열(날짜)`)을 표시한다.
  - 제안 값으로 고치면 그 시트를 선택할 수 있게 된다.
  - 슬롯·시리즈를 고르면 배정 초기화를 확인해야 적용할 수 있다.
  - 적용하면 스냅샷 `가져오기 전 — 시각`을 자동 저장하고, 배정을 실제로 초기화한다. 실행 취소 1단계로 되돌릴 수 있다.
  - `규칙으로 초안 만들기`는 실제 `CalendarGen.generateSlots` 결과와 현재 시트를 비교한다.
- **엔진 실행(목업)**
  - 진행 막대, 점수 추이, 상단 띠의 `실행 중 · 입력 잠금`을 보여 준다. 실행 중에는 격자가 읽기 전용이 되고 잠금 띠가 뜬다.
  - 끝나면 ③으로 넘어간다. 배정이 초기화된 상태였다면 엔진 결과(시드 배정)를 반영한다.
- **결과 수정**
  - 구단 필터(H/A 표식, 다른 구단은 흐리게)를 쓸 수 있다.
  - 위반을 클릭하면 셀로 이동한다.
  - 핀 고정·해제, 슬롯·이벤트 일괄 고정, 풀로 빼기·다시 넣기, 이동 후보 교환(Δ 미리보기)을 할 때마다 `core/score.js`로 즉시 다시 채점한다.
  - 스냅샷을 저장·복원할 수 있다. `엔진 1차 결과`를 복원하면 H1 가상 위반이 사라진다.
- **시즌 운영**
  - 날짜를 고르고 일괄 완료·취소(사유)를 기록하면 재편성 대상 수가 바로 바뀐다.
  - 재편성 실행은 진행 표시는 목업이고, 결과는 `core/reschedule.js`의 실제 탐색(`createSearch`)으로 만든다. RH 규칙으로 확인한다.
- **설정**: 기능을 끄면 해당 탭·열·버튼·창이 DOM에서 사라진다(M2 Δ 열, M8 풀 탭, V6 매트릭스 탭, A4~A12 시트, P2 강조, P7 현황, D4 CSV 버튼, T7 히트맵, T4 드래그 안내). 상태는 `localStorage`에 try/catch로 저장한다. H0-e 모드를 바꾸면 다시 채점한다.

## 목업인 것

화면에 `목업` 꼬리표로 표시한 것들이다.

- .xlsx 파싱과 구글 시트 요청: 미리 준비한 미리보기를 띄운다.
- 빈 양식·예시 파일, .xlsx 내보내기: 알림만 띄운다.
- 엔진 실행: 진행과 점수 추이를 합성한다.
- REST 엔진 연결 시험, Kakao 키 적용
- 재편성 진행 막대: 결과는 실제로 계산한다.

- **① 편집은 채점기에 바로 닿지 않는다.** ①의 셀 편집과 행 삽입·삭제는 워크북 시트 모델에만 반영된다. 검증과 ② 사전 점검은 바로 다시 계산한다. ③·④는 (목업) 실행 전까지 시드 배정을 그대로 채점하고, ③ 요약에 `입력 변경됨 — ② 재실행 필요`를 표시한다.

프로젝트 JSON·엔진 JSON·CSV 내보내기는 공통 컨트롤러 기능으로 실제 파일을 내려받는다.

## 알려진 한계

- **드래그 앤 드롭이 없다.** 시리즈 이동은 셀 상세의 `이동 후보 교환`(Δ 미리보기 포함, 키보드·마우스)과 풀로 빼기·넣기로 한다. 기준 FR-M1 드래그는 최종 제품에서 구현할 몫이다.
- 가상 위반 H0-f와 H1은 교환 한 번으로 풀리지 않는다. 위반이 슬롯 통교환·홈원정 뒤집기로 생겼기 때문이다. `스냅샷 › 엔진 1차 결과`를 복원하면 H1이 사라진다. 셀 상세에 이 안내를 띄운다.
- 실제 .xlsx 파서·쓰기, 구글 시트 요청, 범위 선택·붙여넣기는 범위 밖이다.

## 점검 결과

- **페이지 스크롤**: 헤드리스 Chrome `--dump-dom`으로 `?debug=scroll`이 남긴 `data-scroll` 속성을 읽었다. 위 18개 화면 모두 뷰포트 1440×790과 1920×970에서 `OK`다(문서 크기 = 뷰포트, 세로·가로 스크롤 0). 모달·팝업·메뉴도 고정 위치이고 화면 안으로 제한한다.
- **콘솔 오류**: `<head>` 첫 스크립트가 `error`·`unhandledrejection`·`console.error`를 `data-errors`에 센다. 18개 화면 × 2크기 모두 0건이다.
- **상호작용**: iframe 시험 페이지로 37개 항목을 자동 확인했고, 37개 모두 통과했다. 단계·시트 전환, 셀 선택 → 수식 줄, 방향키, F2·Esc·Enter, 오류 표식, 실행 취소, 행 삽입·삭제, 행 메뉴, 가져오기 고치기·확인·적용·되돌리기, 엔진 잠금·종료, 구단 필터, 위반 → 셀, 핀, 교환, 스냅샷 복원, 달력, 시즌 운영 취소 기록, 재편성, 기능 끄기 → DOM 제거, Must 잠금을 다뤘다.
- 참고: 헤드리스 `--screenshot`은 창 크기 그대로 찍고, `--dump-dom`은 창 높이에서 87px를 뺀 뷰포트를 쓴다. 그래서 스크린샷은 1440×790·1920×970 창으로, 스크롤 점검은 1440×877·1920×1057 창으로 했다. 측정값을 쓰는 격자·차트는 `ResizeObserver`로 다시 그린다.

## 강점과 약점

**강점**
- 가져온 시트와 화면이 탭·열·행 번호까지 1:1이다. 오류 주소(`시트 n행 X열(머리글)`)를 엑셀에서도 화면에서도 같은 방식으로 찾는다.
- 다섯 부품(명령 띠·수식 줄·격자·시트 탭·작업 창)의 자리가 모든 단계에서 같다. 단계가 바뀌어도 눈이 갈 곳이 그대로다. 밀도가 가장 높아 225행 시리즈와 45슬롯 결과를 한 화면에서 훑는다.
- 셀 단위 감사가 쉽다. 수식 줄이 "이 값은 어디서 왔나"(자동 값, 계산 열, 위반 코드)를 바로 보여 준다.
- 1920 폭은 격자 열·달력 칸·차트 개체가 그대로 가져간다.

**약점**
- 한 번에 시트 하나만 보인다. 입력과 결과가 탭으로 갈라지는 문제는 작업 창 미리보기와 단계 요약이 일부만 메운다.
- 흐름·공정성 같은 시각 판단은 표가 1순위이고, 차트는 개체·차트 시트로 한 단계 뒤에 있다.
- "엑셀과 같다"는 기대 때문에 범위 선택, 붙여넣기, 채우기 핸들 요구가 따라올 수 있다(이번 범위 밖).
- 사무용 도구 언어라 회의 자료·보고서용으로는 차갑게 보일 수 있다.
