# alt-b 단계 레일 (Step Rail)

> 브랜치 `wizard-ui/alt-b` · 요구사항 `KBO_WIZARD_UI_REQUIREMENTS.md` §8 alt-b · 고충실도 클릭 시안(기능은 목업)

## 콘셉트

**왼쪽 세로 레일 + 넓은 작업대의 좌우 라이브 분할.**

- 레일에는 4단계(① 데이터 준비 ② 검토·실행 ③ 결과·수정 ④ 품질·배포)가 노드와 연결선으로 놓인다. 단계마다 상태(✔ 완료 · ⚠ 확인 필요 · ⛔ 차단 · ○ 작성 중, 아이콘 + 글자)와 한 줄 요약을 붙인다. 지금 단계의 하위 탭은 그 단계 바로 아래에 펼쳐진다. 레일은 아이콘 띠(64px)로 접을 수 있고(`[` 키), 접은 상태는 이 브라우저에 기억된다.
- 레일 아래쪽에 위저드와 떨어진 **시즌 운영**과 **설정**을 둔다. 상단 띠에도 같은 메뉴가 있다(§3.2).
- 작업대는 언제나 **왼쪽 = 입력·조치, 오른쪽 = 그 입력의 즉시 결과**다. 두 패널 사이의 작은 ▶ 연결점과 오른쪽 머리의 `즉시 결과` 표식으로 이 관계를 알린다. 왼쪽에서 바꾸면 오른쪽의 큰 숫자가 다시 계산되고 노란 깜빡임으로 바뀐 칸을 알려 준다.
  - ① 슬롯 표에서 연전을 3 → 4로 고치면, 오른쪽 연전 수급 막대가 `부족 5`로 바뀌고, 레일 ②가 ⛔ 차단으로, 상단 배지가 H0-d 위반으로 바뀐다.
  - ③ 위반을 누르면 캘린더가 그 달·슬롯으로 이동해 강조된다. 오른쪽 시리즈 상세에는 교환 후보와 Hard·km 변화량(Δ)이 나온다.
  - 시즌 운영에서 월요일·DH 옵션을 바꾸면 수용 게이지가 바로 바뀐다.
- 페이지 스크롤이 없는 고정 화면이다. 1920 폭에서는 늘어난 폭을 본문에 준다: ③ 캘린더가 **두 달을 나란히** 보이고, 표는 열이 넓어지고, 차트는 더 큰 캔버스로 그린다.

## 실행

```bash
open index.html                     # file://로 바로 열기 (라이브러리·웹 폰트·네트워크 없음)
open "index.html?debug=scroll"      # 상단 띠에 페이지 스크롤 점검 표시
open "index.html?selftest=1"        # 상호작용 자가 점검 (<html data-selftest>에 결과)
tools/all-shots.sh both             # 필수 화면 캡처 + 스크롤 점검 (헤드리스 Chrome)
```

- 프로젝트 상태는 새로 열 때마다 같은 상태(2025 프리셋 + 가상 위반 3건)로 시작한다. **기능 켜기·끄기와 레일 접힘만** `localStorage`(`kbo-wizard-alt-b:*`, try/catch)에 저장한다. `?fresh=1`은 이 저장값을 지운다.
- 화면 코드는 `app/rail/`에 있다. `core/`(프리셋·채점기·재편성)는 그대로 쓰고, `core/store.js`의 실행 취소·스냅샷도 그대로 쓴다. `app/common/` 패널은 쓰지 않는다.

| 파일 | 내용 |

## 강점과 약점

**강점**
- 원인과 결과가 늘 옆에 있다. 처음 시즌을 짜는 사람이 “이 값을 바꾸면 무엇이 깨지는지”를 입력하는 순간 본다(연전 수급, 수용 게이지, Δ).
- 레일이 위치와 다른 단계 상태를 항상 보여 준다. 하위 탭이 단계 아래에 붙어 있어 상단 탭 두 줄(단계 + 하위)이 필요 없고, 세로 공간을 본문에 준다.
- 접으면 64px 아이콘 띠가 되어 1440에서도 캘린더를 넓게 쓸 수 있다. 1920에서는 캘린더가 두 달을 나란히 보여 준다.
- 큰 요약 숫자와 따뜻한 지면 덕분에 차분하고, 화면마다 “한 가지 할 일”이 분명하다.

**약점**
- 레일(256px)과 오른쪽 결과 패널(약 400px)을 빼면 1440에서 왼쪽 입력 영역이 700px 남짓이다. 225행 시리즈 표나 캘린더는 alt-a·alt-c보다 좁고, 캘린더는 마지막 주를 패널 안에서 스크롤해야 한다.
- 화면마다 오른쪽 결과 패널을 따로 설계해야 해서 화면 수가 늘수록 유지 비용이 크다. ④ 차트처럼 결과가 곧 본문인 화면에서는 좌우 분할 문법이 약해진다(목록 ↔ 큰 차트).
- 레일과 상단 띠 양쪽에 시즌 운영·설정 입구가 있어 중복이다(요구사항 §3.2와 이 후보의 레일 배치를 함께 만족시키려는 선택).
- 위반 수정은 교환 후보 목록으로만 한다. 캘린더 드래그 앤 드롭(FR-M1)은 이번 시안에 넣지 않았다.
