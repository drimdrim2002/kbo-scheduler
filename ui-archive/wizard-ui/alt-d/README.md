# alt-d 브리프 스프레드 (Brief Spread)

> 브랜치 `wizard-ui/alt-d` · 요구사항 `KBO_WIZARD_UI_REQUIREMENTS.md` §8 alt-d · 진입점 `index.html` (`file://`로 바로 열림)

## 콘셉트

opus-ui alt-1 "편성 브리프"의 **종이 보고서 언어와 장(章) 구성**을 그대로 두고, 세로로 길게 내려가던 문서를 **가로로 펼친 책 한 면**으로 바꾼 위저드다.

- 위에는 보고서 목차 같은 **장 탭 4개**(제1장 데이터 준비 · 제2장 검토·실행 · 제3장 결과·수정 · 제4장 품질·배포)가 있다. 탭마다 상태(✔ 완료 · ⚠ 확인 필요 · ⛔ 차단 · ○ 작성 중)와 한 줄 요약이 붙는다.
- 장을 **확정**하면 alt-1처럼 한 줄 요약 카드로 접힌다. 카드는 탭 아래 **얇은 띠**에 가로로 쌓이고, "다시 열기"로 돌아간다.
- 장 안은 **좌우 2단 펼친 면**이다. 왼쪽 넓은 단은 본문(표·캘린더·차트), 오른쪽 좁은 단은 책의 **여백**(요약, 주석, 점검 메모, 선택한 항목 상세)이고, 여백 맨 아래에 고정된 **"다음 할 일"**이 있다.
- 장 안의 절(1.1, 1.2 …)은 탭으로 바꾼다. 긴 스크롤은 없다. 아래 쪽번호 띠는 "◀ 이전 장 / — 3 — 제3장 결과·수정 / 이 장 확정 · 다음 장 ▶"이다.
- 표와 그림에는 보고서 캡션("표 4.1 구단별 지표", "그림 2.1 점수 추이")을 붙인다. 시트 이름과 표 번호를 맞춰("시트 '슬롯' ↔ 표 1.2") 가져온 엑셀과 화면이 1:1로 대응한다.
- 시즌 운영은 위저드 밖의 **별책**(상단 메뉴 "시즌 운영")이다. 설정은 모달이다.

## 실행

```bash
open index.html                       # 기본: 제1장
open "index.html?fresh=1"             # 저장 상태를 지우고 2025 프리셋(가상 위반 3건)으로 시작

tools/shoot.sh                        # 스크린샷 34장 + 스크롤 점검 (headless Chrome)
```

## 상호작용 (실제로 동작)

- 장 전환, 절 탭, 이전 장/다음 장(다음 장 버튼에 현재 장 상태), 장 확정 → 요약 카드 → 다시 열기.
- 한 건 편집: 행 클릭 선택, 더블클릭·Enter·F2 편집, ↑↓ 행 이동, Tab 다음 셀. 입력 즉시 검증해 셀 아래에 오류를 띄운다(알 수 없는 구단 + 비슷한 이름 제안 버튼, 홈 = 원정, 연전 2~4, 슬롯 날짜 겹침, 날짜 형식 `5/20`·`2025.5.20`·`5/20(화)`·엑셀 일련번호). 위에 삽입·아래 삽입·삭제가 실제로 표를 바꾸고(배정·메모 인덱스도 함께 옮김), ⌘Z/⌘⇧Z로 되돌린다.
- 가져오기: .xlsx 업로드/구글 시트 연결 → 미리보기(시트별 행·+추가 ~변경 −삭제, 오류 2건·경고 5건, 시트 선택) → 오류 고치기 제안 → 배정 초기화 확인 → 적용(자동 스냅샷 "가져오기 전 — 시각", 실행 취소 1단계). 보조 생성("규칙으로 초안 만들기", "구단쌍 규칙으로 만들기")은 실제 규칙으로 만든 결과를 같은 미리보기로 보여 준다.
- 사전 점검 링크 → 제1장 해당 절로 이동하고 탭을 깜빡인다. 엔진 실행(목업): 진행률·경과·개선 횟수·점수 추이가 0.25초마다 바뀌고, 상단에 "⊘ 입력 잠김"이 뜨며 편집·이동·가져오기가 막힌다. 일시정지·중지 가능, 끝나면 제3장으로 넘어간다.
- 캘린더: 월 탭, 구단 필터(해당 대진 굵게 + 홈/원정 태그, 나머지 흐리게), 위반 블록 이중 빨간 테두리 + ⛔ 코드, 대진 클릭 → 여백 상세, 위반 클릭 → 해당 달·슬롯 강조, 핀 토글, 교환 후보 클릭/끌어 놓기 맞바꾸기(Δ 미리보기), 미배정 풀, 실행 취소, 스냅샷 저장·복원(원본 initialPlan 스냅샷 복원 시 H1이 실제로 사라짐).
- 품질: 열 정렬, 행·막대·점 클릭으로 구단 강조, 구단별 일정표 선택, 인쇄(인쇄 CSS로 일정표 한 장만 A4에 출력).
- 시즌 운영: 날짜 선택, 경기 상태 기록, 그날 일괄 완료/취소(사유), 재편성 옵션, 재편성 실행 → 9~10월 결과와 RH-1~5 점검.
- 설정: 기능 끄기 → 해당 요소가 DOM에서 사라짐(예: M8 끄면 미배정 풀·"풀로 빼기" 버튼, A11 끄면 4.4 탭, V6M 켜면 3.3 탭), `meta.features`에 저장. H0-e 모드를 바꾸면 배지와 채점이 바뀐다.

## 목업인 것 ("목업" 표시)

| 기능 | 시안의 동작 |
| :--- | :--- |
| .xlsx 파싱, 구글 시트 CSV 요청 | 버튼을 누르면 미리 준비한 결과(오류 2·경고 5)로 미리보기를 띄운다. 적용하면 공휴일 6/3 추가와 배정 초기화만 실제로 반영한다 |

| 엔진 실행 | 6.4초 동안 진행률·점수 추이를 재현하고, 끝나면 시안용 배정(가상 위반 3건)을 다시 놓는다. 실제 Mock 솔버는 부르지 않는다 |

| REST 엔진, Kakao 지도 | 설정 값만 저장한다 |

## 강점과 약점

강점
- alt-1의 읽는 흐름(장 → 절 → 표·그림 캡션 → 확정 요약)과 인쇄 품질을 유지하면서 페이지 스크롤을 없앴다. 회의 자료로 띄워 놓고 장 탭만 넘겨도 설명이 된다.
- 여백 단이 "이 화면에서 무엇을 봐야 하고 다음에 무엇을 하나"를 항상 같은 자리에서 알려 준다. 위반 상세도 여백 한 곳에만 있다.
- 시트 이름과 표 번호를 맞춰 엑셀 왕복이 화면 구조에 드러난다. 캘린더가 슬롯을 하나의 블록으로 그려 같은 대진이 사흘 반복되지 않는다.

약점
- 여백 단이 300px로 좁아, 위반이 많거나 시리즈 상세·교환 후보를 함께 볼 때 여백 안에서 스크롤해야 한다(alt-a 인스펙터보다 좁다).
- 고정 골격(상단 띠·장 탭·카드 띠·쪽번호 띠)이 172px를 차지해 1440×790에서 본문 높이가 618px로 빠듯하다. 6주짜리 달은 블록이 낮아진다.
- 명조 제목과 상아색 지면은 보고서다운 대신, 하루 종일 쓰는 편집 도구로는 대비가 부드럽고 정보 밀도는 엑셀형(alt-c)보다 낮다.
- 시스템 명조는 OS마다 다르다(macOS AppleMyungjo, Windows 바탕). Windows에서는 제목 인상이 달라진다.

## 알려진 빈틈

- 기능 T4(지도 마커 드래그)를 켜면 문구와 "목업" 표시만 바뀌고 드래그 처리는 없다. 거리 행렬 히트맵(T7)은 읽기 전용이다.
- 기능 레지스트리는 `app/spread/features.js`에 있다(최종 제품에서는 `app/common/features.js`).
- 목업 엔진 실행은 끝날 때 시안용 배정(가상 위반 3건)을 다시 놓는다. 핀 고정 시리즈만 그 자리에 둔다.
- 공통 컨트롤러가 쓰는 `kbo-opus:engine`, `kbo-opus:kakao-key` localStorage 키는 같은 `file://` 출처의 다른 후보와 공유된다(base에서 물려받음).
- 1440 미만 해상도는 지원하지 않는다(1280 미만에서 안내 띠).
