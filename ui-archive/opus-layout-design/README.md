# KBO 일정 편성 UI: 세로 스크롤이 아닌 레이아웃 대안

> 작업 폴더 `opus-layout-design/`.
> 요구사항 기준은 [`../KBO_OPUS_UI_REQUIREMENTS.md`](../KBO_OPUS_UI_REQUIREMENTS.md)의 §3 사용자·시나리오, §5 기능, §10 대안 구성입니다.

## 0. 열어 보기

| 파일 | 내용 |
| :--- | :--- |
| `index.html` | 대안 5개 모음, 비교표, 추천안. 여기서 시작합니다. |
| `layout-a.html` | A. 라이브 스플릿: 입력(왼쪽)과 즉시 미리보기(오른쪽) |
| `layout-b.html` | B. 레코드 탐색기: 목록, 상세, 인스펙터 |
| `layout-c.html` | C. 가로 진행 컬럼: 단계가 가로로 늘어서고 집중한 단계만 펼침 |
| `layout-d.html` | D. 레이어 타임라인: 시간축 하나에 입력·결과 트랙을 쌓음 |
| `layout-e.html` | E. 편성 워크북: 시트 탭, 수식 줄, 검증 창 |
| `data.js` | `data/baseball/input_2025.json`에서 뽑은 더미 데이터. 구단 10, 슬롯 45, 시리즈 225, 거리 행렬은 실제 값이고, Hard 위반 3건은 가상입니다. |
| `common.js`, `wire.css` | 공통 헬퍼와 스타일: Hard 배지, 구단별 지표 표, 홈/원정 스트립, §5.2.1 슬롯 생성기, 주석 핀, 페이지 스크롤 점검 |

- 라이브러리, CDN, 빌드가 없습니다. `file://`로 바로 열립니다. 데이터는 `fetch`가 아니라 `<script src>`로 읽기 때문에 `file://`에서도 막히지 않습니다.
- 각 화면 위의 검은 띠는 와이어프레임 도구이고, 앱의 일부가 아닙니다.
  - **주석 보기 (N 키)**: 화면 영역마다 번호 핀과 설명이 나타납니다.
  - **페이지 스크롤 점검**: 문서 전체가 뷰포트보다 커지면 초록에서 빨강으로 바뀝니다. 탭을 바꾸거나 패널을 열 때마다 다시 검사합니다.
- `common.js`의 슬롯 생성기는 §5.2.1 규칙을 그대로 구현했습니다. 2025 기본 설정에서 `input_2025.json`의 45개 슬롯과 날짜·연전 수·가중치까지 모두 일치합니다(Node로 확인). A와 D는 입력을 바꾸면 이 생성기로 슬롯을 실제로 다시 계산합니다.

## 1. 문제 정의: 세로로 긴 화면이 입력·확인 작업에 불리한 이유

지금까지의 대안(opus-ui alt-1 편성 브리프, alt-2 시즌 보드, alt-3 구단 매트릭스)은 공통적으로 페이지가 세로로 길어집니다. 이 도구의 작업 특성과 맞춰 보면 다음 문제가 생깁니다.

1. **원인과 결과가 서로 다른 스크롤 위치에 있다.** 휴식 요일이나 경기 없는 기간을 바꾸면 슬롯 45개, 연전 분포, 사전 점검(§5.4 FR-R2)이 함께 바뀝니다. 그런데 그 결과는 몇 화면 아래에 있습니다. 사용자는 "바꾼다 → 내려간다 → 확인한다 → 올라온다"를 반복하면서, 바꾸기 전 값을 머리로 기억해야 합니다.
2. **기준점이 화면 밖으로 사라진다.** Hard 위반 배지, 실행 버튼, 지금 단계 같은 정보는 늘 보여야 합니다. 세로 문서에서는 sticky 처리를 해도 섹션이 늘어날수록 기준점이 화면에서 밀려납니다.
3. **확인 루프가 길다.** 결과 확인은 "위반 발견 → 위치 → 원인 → 조치 → 재채점"의 반복입니다(SC-2). 목록과 위치와 조치 버튼이 세로로 떨어져 있으면 한 바퀴마다 스크롤을 왕복해야 합니다.
4. **주 사용자는 엑셀 숙련자다.** 엑셀은 페이지 스크롤이 없는 고정 창이고, 그 안의 격자만 두 방향으로 움직입니다. 세로 문서는 이 사용자에게 오히려 낯선 모델입니다.

### 평가 기준

| 코드 | 기준 | 질문 |
| :--- | :--- | :--- |
| K1 | 인과 가시성 | 값을 입력하는 동안 그 결과가 같은 화면에 보이는가 |
| K2 | 위치 감각 | 전체 작업 중 어디에 있는지, 다른 단계의 상태를 알 수 있는가 |
| K3 | 확인 루프 길이 | 위반 발견에서 조치까지 몇 번의 이동이 필요한가 |
| K4 | 익숙함·밀도 | 엑셀 숙련자가 바로 쓸 수 있는가, 대량 데이터(시리즈 225, 거리 100칸)를 다룰 수 있는가 |
| K5 | 시즌 생애주기 | 취소 기록과 9~10월 재편성(SC-4, SC-5)이 자연스럽게 들어갈 자리가 있는가 |
| K6 | 스크롤 정책 | 페이지 스크롤 없이, 패널마다 한 방향으로만 스크롤하는가 |

### 공통 원칙 (5개 와이어프레임 모두 적용)

- `html, body { height: 100%; overflow: hidden }`에 루트 grid를 두고, 스크롤은 지정한 패널 안에서만 일어납니다. grid·flex 자식에 `min-height: 0` / `min-width: 0`을 주어, 안쪽 내용이 페이지를 밀어내지 못하게 했습니다.
- **1280×800 화면**은 브라우저 창 틀을 빼면 실제 뷰포트가 약 **1280×700**입니다. 두 크기 모두 헤드리스 Chrome으로 확인했고, 다섯 화면 모두 페이지 스크롤이 0입니다.
- Hard 상태 배지(FR-V4: 색 + 아이콘 + 글자)는 모든 화면 상단에 항상 보입니다.

## 2. 대안 상세

### A. 라이브 스플릿: 입력 ↔ 즉시 미리보기 (`layout-a.html`)

**핵심 아이디어.** 마크다운 편집기처럼 왼쪽에서 쓰고 오른쪽에서 바로 결과를 봅니다. 입력값과 그 파생 결과(슬롯 생성, 연전 분포, 사전 점검)를 같은 화면에 나란히 둡니다.

```
┌────────────────────────────────────────────────────────────┐
│ 제목 │ ①입력 ②결과 확인 ③시즌 운영 │      [Hard 배지] [실행] │
├──────────────────┬─────────────────────────────────────────┤
│ 입력 탭           │ 실시간 미리보기 (왼쪽 탭에 연동)          │
│ 구단|골격|이벤트|시리즈 │ 핵심 수치 5개 (바뀐 만큼 +n 깜빡임)    │
│ ─────────────    │ 3~10월 일자 띠 (경기일·휴식·경기 없는 기간…) │
│ 폼 (내부 세로 스크롤) │ 슬롯 칩 목록 (내부 스크롤)              │
│                  │ ─ 사전 점검 (항상 하단 고정) ──────────── │
└──────────────────┴─────────────────────────────────────────┘
```

- **입력 → 확인 흐름.** 휴식 요일을 체크하면 오른쪽의 슬롯 수, 2/3/4연전 분포, 일자 띠, 사전 점검이 즉시 다시 계산됩니다. 수급이 깨지면 "✕ 차단"이 뜨고 실행 버튼이 비활성화됩니다. 경기 없는 기간 행에 마우스를 올리면 오른쪽 달력에서 그 날짜가 강조됩니다. 왼쪽 탭을 바꾸면 오른쪽도 따라 바뀝니다: 구단 → 거리 행렬, 시리즈 → 구단쌍 행렬.
- **결과·운영 단계도 같은 문법.** 왼쪽은 조치(위반 목록, 핀, 재최적화) 또는 취소 기록·재편성 옵션이고, 오른쪽은 반영 결과(구단별 홈/원정 흐름, 지표 표) 또는 재편성 수용 게이지입니다.
- **장점.** K1이 가장 강합니다. 최적화 비전문가가 구조적 불가능(§5.4 FR-R2)을 실행 전에, 입력하는 순간 알아챕니다. 왼쪽에서 바꾸고 오른쪽에서 확인한다는 규칙 하나만 익히면 됩니다.
- **단점.** 오른쪽 미리보기를 탭마다 따로 설계해야 합니다. 화면 폭의 절반을 미리보기에 쓰므로, 입력 폼이 넓어야 하는 시리즈 225행 같은 대량 편집에는 좁습니다. 결과 단계에서 드래그 수정 공간이 작습니다.
- **적합.** SC-1(새 시즌 입력), SC-5의 옵션 조정(월요일·DH를 켜면 수용 게이지가 바로 바뀜). 페르소나는 편성 담당자 중 처음 쓰는 사람과 가끔 쓰는 사람.
- **스크롤.** 페이지 0. 왼쪽 폼만 세로 스크롤하고, 오른쪽은 수치·달력·점검을 고정한 채 슬롯 목록만 스크롤합니다.
- **기존안과 차이.** gemini 3분할 워크스페이스는 세 영역에 서로 다른 일을 나눠 줍니다. A는 두 영역이 같은 데이터의 원인과 결과입니다. alt-1(문서형)은 입력과 결과가 위아래에 있습니다.

### B. 레코드 탐색기: 목록, 상세, 인스펙터 (`layout-b.html`)

**핵심 아이디어.** 메일이나 Finder처럼, 모든 것을 레코드(구단, 슬롯, 시리즈, 이벤트, 위반, 경기 기록)로 다룹니다. 목록에서 하나를 고르면 상세가 뜨고, 상세 안의 링크를 따라 관련 레코드로 옮겨 갑니다.

```
┌────────────────────────────────────────────────────────────┐
│ 제목 │ [전역 검색: 한화, 5/20, KIA@삼성 …]  [Hard 배지] [실행]  │
├───────────────┬────────────────────────────────────────────┤
│ 유형 8개 버튼   │ ← 뒤로  위반 › 슬롯 › 시리즈 (이동 경로)        │
│ 개요 구단 슬롯… │ 제목 · 상태                                 │
│ 거르기 · 정렬   ├──────────────────────────┬─────────────────┤
│ ───────────   │ 확인 영역 (내부 스크롤)      │ 인스펙터          │
│ 레코드 목록     │ 지표 카드·흐름·관련 레코드 표 │ 속성 편집·핀      │
│ (내부 스크롤)   │ 대상 슬롯 + Δ 미리보기 목록   │ (내부 스크롤)     │
└───────────────┴──────────────────────────┴─────────────────┘
```

- **입력 → 확인 흐름.** 위반 목록에서 H0-f를 고릅니다. 원인 설명, 해당 구단 흐름, 해결 제안과 그 Hard/Soft Δ가 보이고, "적용"을 누르면 끝납니다. 슬롯이나 구단 링크를 따라가며 원인을 추적하고, "뒤로"로 돌아옵니다. 입력은 오른쪽 인스펙터에서 합니다(구단 속성, 슬롯 가중치, 핀). ↑↓ 키로 목록을 넘기면 상세가 그대로 따라옵니다.
- **장점.** K3이 가장 짧습니다(위반 → 원인 → 조치가 한 화면). 시리즈 상세의 "대상 슬롯 + Δ" 목록이 드래그의 키보드 대안(FR-M1, FR-M2)을 자연스럽게 해결합니다. 레코드 유형이 늘어도 구조가 그대로입니다. 경기 기록이나 재편성도 유형 하나를 추가하면 됩니다.
- **단점.** 시즌 전체를 한눈에 보는 개요가 약합니다(K2). 레코드 하나씩 보는 구조라 "구단 간 공정성 비교" 같은 전체 판단에는 표나 차트 화면을 따로 붙여야 합니다. 입력 순서를 안내하지 않으므로 처음 쓰는 사람은 무엇부터 할지 모릅니다.
- **적합.** SC-2(위반 해결, 시리즈 이동·고정), SC-4(특정 날짜 경기 기록), 구단 운영팀의 "우리 구단" 조회. 페르소나는 숙련 편성 담당자와 민원 대응 담당자.
- **스크롤.** 페이지 0. 목록, 확인 영역, 인스펙터가 각자 세로로만 스크롤합니다.
- **기존안과 차이.** gemini 3분할 워크스페이스는 왼쪽에 작업 단계 독이 있는 단계 중심 구조입니다. B에는 단계 내비게이션이 없고, 고른 레코드와 그 관계가 탐색의 축입니다.

### C. 가로 진행 컬럼: 모든 단계를 늘 보여 주기 (`layout-c.html`)

**핵심 아이디어.** 칸반이나 파이프라인처럼 단계 7개(구단 → 골격 → 이벤트 → 검토·실행 → 결과 → 분석 → 시즌 운영)를 가로 한 줄에 놓습니다. 집중한 단계 하나만 넓게 펼치고, 바로 앞 단계는 "곁보기" 요약으로, 나머지는 52px 세로 띠로 접습니다.

```
┌──┬──┬──┬────────────┬──────────────────────────────┬──┬──┐
│1 │2 │3 │ 4 검토·실행  │ 5 결과 확인 (집중)              │6 │7 │
│구│일│이│ (곁보기)     │ 구단 강조 버튼                   │지│시│
│단│정│벤│ 엔진 요약    │ 슬롯 목록: 날짜 · 5대진 · 위반      │표│즌│
│  │  │트│ 점수 추이    │ (이 컬럼만 내부 세로 스크롤)        │  │  │
│✓ │✓ │✓ │             │ [수정 제안] [스냅샷] [재최적화]     │▲7│38│
└──┴──┴──┴────────────┴──────────────────────────────┴──┴──┘
   접힌 띠: 번호·이름·상태 (세로 글씨)          ← → 키로 이동
```

- **입력 → 확인 흐름.** 이벤트를 넣을 때는 곁보기에 일정 골격의 슬롯 목록이 있어서, 날짜를 보면서 대진을 지정합니다. 결과 컬럼을 볼 때는 곁보기에 엔진 실행 요약이 있습니다. 엔진을 실행하면 결과 컬럼이 자동으로 펼쳐집니다. 접힌 띠에도 "✓ / ! Hard 3 / 취소 38" 같은 상태가 남아 있어서, 어느 단계에 문제가 있는지 늘 보입니다.
- **장점.** K2가 가장 강합니다. 위저드와 달리 다른 단계가 사라지지 않고, 어느 단계로든 한 번에 갈 수 있습니다. "이전 단계의 산출물을 보면서 지금 단계를 입력"하는 흐름이 공간 배치로 드러납니다. 가로 흐름이지만 1280px 안에 다 들어가서 가로 스크롤이 없습니다.
- **단점.** 집중 컬럼 폭이 약 660px로 제한됩니다. 구단×슬롯 매트릭스나 대형 달력처럼 넓은 결과 보기는 넣기 어렵습니다. 단계가 8개 이상으로 늘면 띠가 좁아집니다. 곁보기가 늘 바로 앞 단계로 고정되어 있어서, 다른 단계를 참고하려면 기능을 더 만들어야 합니다.
- **적합.** SC-1 전체 흐름, 그리고 회의에서 진행 상황을 보여 줄 때. 페르소나는 처음 쓰는 사람과 의사결정자.
- **스크롤.** 페이지 0, 가로 0. 집중 컬럼과 곁보기 컬럼만 각자 세로 스크롤합니다.
- **기존안과 차이.** gemini 위저드는 한 번에 한 단계만 보이고 순서가 강제됩니다. C는 모든 단계가 동시에 보이고 순서가 자유롭습니다. alt-1(문서형)의 섹션 순서를 세로에서 가로로 돌리되, 접기로 화면 밖으로 밀려나지 않게 했습니다.

### D. 레이어 타임라인: 입력과 결과를 시간축 하나에 겹쳐 쌓기 (`layout-d.html`)

**핵심 아이디어.** 영상 편집기(NLE)처럼 시간을 가로축으로 두고, 그 위에 트랙을 쌓습니다. 위쪽 트랙은 사람이 넣는 입력 레이어(휴식·예외, 공휴일, 경기 없는 기간, 이벤트)이고, 아래쪽 트랙은 계산 결과 레이어(슬롯, Hard 위반, 경기 기록, 구단 흐름)입니다.

```
┌────────────────────────────────────────────────────────────┐
│ 제목 │ 전체 / 1차 / 재편성 │ 확대 ± │ [입력 변경됨] [배지] [실행] │
│ ▁▁▁▁[████ 보이는 구간 ████]▁▁▁▁▁▁▁▁▁▁░░░░ 미니맵 (위반 눈금)  │
├────────────┬───────────────────────────────────────────────┤
│ 트랙 (고정)  │ 3월 ··· 5월 ··· 6월 ···  (날짜 눈금 고정)        │
│ 휴식·예외 입력│ ▨  ▨  ▢  ▨                                    │
│ 공휴일   입력│     ◆        ◆                                 │
│ 경기없는기간 │        [올스타]                                 │
│ 이벤트   입력│   ★어린이날                                     │
│ 슬롯 45 자동│ [3][3] [3][3][3] [3] …   ← 입력하면 즉시 재계산    │
│ 위반 3  결과│          [⚠H0-f]      [⚠H1]                     │
│ 경기 기록   │ ▮▮▮✕▮▮ …           ┆오늘                       │
│ ▾ 구단 흐름 │ SSG ■□■■□ …  (10줄)                             │
├────────────┴───────────────────────────────────────────────┤
│ 도크: 선택 항목 | 위반 목록 | 구단 지표 | 취소·재편성 (고정 높이)   │
└────────────────────────────────────────────────────────────┘
```

- **입력 → 확인 흐름.** 입력은 시간축 위에 직접 합니다. "경기 없는 기간" 트랙의 빈 곳을 클릭하면 기간이 생기고, 휴식(빗금) 칸을 클릭하면 휴식 예외가 됩니다. 바로 아래 슬롯 트랙이 §5.2.1 생성기로 즉시 다시 계산되고, 새로 생긴 슬롯은 점선으로 표시됩니다. 엔진 결과와 달라지면 상단에 "입력 변경됨 — 결과는 이전 실행 기준"이 뜹니다. 슬롯이나 ⚠를 클릭하면 세로 선택 띠가 모든 트랙을 관통하고, 하단 도크에 그 슬롯의 5대진·가중치·위반이 나옵니다.
- **장점.** 날짜 입력(휴식, 예외, 경기 없는 기간, 공휴일, 이벤트)과 그 영향을 같은 시간축에서 보므로 K1이 A만큼 강합니다. 1차 편성, 취소 기록, 오늘 선, 9~10월 재편성 구간이 하나의 축에 이어져서 K5가 가장 자연스럽습니다. 미니맵으로 시즌 전체(K2)도 유지합니다.
- **단점.** 구단 정보, 거리 행렬, 시리즈 목록처럼 시간과 무관한 입력은 넣을 자리가 없습니다(도크나 별도 화면 필요). 가로 스크롤과 확대 개념이 처음 쓰는 사람에게 낯설 수 있습니다. 트랙이 많아지면 세로 공간이 부족합니다.
- **적합.** SC-1의 일정 골격·이벤트 입력, SC-4 취소 기록, SC-5 재편성. 페르소나는 날짜 단위로 일하는 편성 담당자와 시즌 중 운영 담당자.
- **스크롤.** 페이지 0. 타임라인 영역 하나만 가로·세로로 스크롤하고, 트랙 이름 열과 날짜 눈금은 sticky로 고정합니다. 도크는 고정 높이에 내부 스크롤입니다.
- **기존안과 차이.** alt-2 시즌 보드는 주 단위로 꺾인 월간 달력이라 시즌 흐름이 끊기고 세로로 깁니다. D는 끊김 없는 한 줄 시간축입니다. alt-3 구단 매트릭스는 행이 구단입니다. D는 행이 입력·결과 레이어이고, 구단 흐름은 접을 수 있는 한 묶음일 뿐입니다. alt-4 원정 지도의 하단 타임라인은 지도를 움직이는 재생 막대이고, D는 타임라인 자체가 편집면입니다.

### E. 편성 워크북: 엑셀 문법 그대로 (`layout-e.html`)

**핵심 아이디어.** 주 사용자가 이미 아는 엑셀 모델을 그대로 씁니다. 모든 입력과 결과가 시트이고, 수식 줄이 선택한 셀의 값·유래·위반을 설명하며, 검증 창이 모든 시트의 문제를 "시트!셀" 주소로 모읍니다.

```
┌────────────────────────────────────────────────────────────┐
│ 리본: 가져오기 내보내기 │ 검토 ▶실행 │ ↶ ↷ 스냅샷 │ [배지] [검증 창] │
│ 결과!S4 │ fx │ @롯데 · 5/20(화) 원정 · LG @ 롯데 · 3연전        │
├──────────────────────────────────────────┬─────────────────┤
│   A    B      C      D   …  (열 머리 고정) │ 검증  13건       │
│ 1 구단 3/22   3/25   …     (항목 행 고정)  │ ⚠ 결과!AG4 H0-b  │
│ 2 SSG  H 롯데 @두산 …                      │ ⚠ 결과!S7  H0-f  │
│ 3 두산 …    ◤위반 셀은 빨간 삼각형           │ ! 지표!B2  S2 …  │
│ (시트 본문만 가로·세로 스크롤)               │ (클릭 → 셀로 이동) │
├──────────────────────────────────────────┴─────────────────┤
│ 입력: 구단 거리 일정골격 이벤트 │ 계산🔒: 슬롯 시리즈 검토 │ 결과: …⚠3 │ 운영: … │
│ 상태 표시줄: 선택 범위 합계·평균 · H0-e 모드 · Hard 배지            │
└────────────────────────────────────────────────────────────┘
```

- **입력 → 확인 흐름.** 입력 시트(구단, 거리, 일정 골격, 이벤트)에 값을 넣으면 계산 시트(슬롯, 시리즈, 검토)가 갱신되고, 문제는 셀 삼각형, 탭 배지, 검증 창 세 곳에 동시에 나타납니다. 예를 들어 슬롯 시트에서 연전 수를 4로 바꾸면 H0-d 경고가 붙고 검토 시트 상태가 바뀝니다. 결과 셀을 고르면 수식 줄에 대진·연전·위반 원인이 나옵니다. Shift+클릭으로 범위를 고르면 상태 표시줄에 합계·평균이 나옵니다.
- **장점.** K4가 가장 강합니다. 학습 비용이 거의 없고, 방향키·Enter·범위 선택 같은 습관이 그대로 통합니다. 225행 시리즈와 10×10 거리 행렬 같은 대량 데이터를 가장 효율적으로 다룹니다. 수식 줄에 "이 값은 어디서 왔나"를 보여 주므로, 비전문가가 자동 생성 규칙을 이해하는 데도 도움이 됩니다.
- **단점.** 한 번에 시트 하나만 보이므로 입력과 그 결과(입력 시트 ↔ 계산 시트)가 탭으로 갈라집니다. 이 약점은 검증 창과 탭 배지가 일부만 메웁니다. K1은 A·D보다 약합니다. 시각적 판단(흐름, 공정성 그래프)은 표보다 약하므로 차트 시트가 따로 필요합니다. "엑셀과 똑같다"는 기대 때문에 수식 입력, 복사·붙여넣기, 채우기 핸들 같은 요구가 따라옵니다.
- **적합.** 엑셀 숙련 담당자의 대량 입력·검수, 전년 데이터를 붙여넣는 작업, 결과 셀 단위 감사. SC-1, SC-3(스냅샷별 지표 시트 비교).
- **스크롤.** 페이지 0. 시트 본문만 두 방향으로 스크롤하고, 열 머리·항목 행·첫 열은 고정합니다. 검증 창은 세로 스크롤, 시트 탭 줄은 탭이 넘치면 가로 스크롤합니다.
- **기존안과 차이.** alt-3 구단 매트릭스는 결과 격자 하나가 주 화면이고 하단에 시트를 엽니다. E는 앱 전체가 워크북이고, 결과 격자는 시트 11개 중 하나입니다. 검증 창과 수식 줄이 확인 수단입니다.

## 4. 추천

### 1순위: A 라이브 스플릿을 기본 골격으로

이 도구에서 가장 비싼 실수는 실행 전에 알 수 있었던 구조적 불가능을 실행 후에야 아는 것입니다. 연전 수급 부족, 이벤트 모순, 1일짜리 구간 같은 것들입니다. 주 사용자는 최적화 비전문가라 입력과 결과 사이의 인과를 머리로 계산하기 어렵습니다. A는 그 인과를 화면 배치로 보여 줍니다. 값을 바꾸는 순간 슬롯 수와 사전 점검이 바뀌고, 차단 항목이 있으면 실행 버튼이 잠깁니다.

규칙도 "왼쪽에서 바꾸고 오른쪽에서 확인한다" 하나라서, 결과 단계(왼쪽 조치 → 오른쪽 반영)와 운영 단계(왼쪽 취소·옵션 → 오른쪽 수용 게이지)까지 같은 문법이 이어집니다.

### 2순위: B 레코드 탐색기를 결과 확인·수정과 시즌 운영 단계에

결과 단계의 핵심은 "위반 → 원인 → 조치"를 짧게 반복하는 것이고, 이 부분은 B가 가장 잘합니다. 링크로 원인을 따라가고, 인스펙터에서 바로 고치고, 대상 슬롯별 Δ를 보고 적용합니다. B도 A와 같은 고정 뷰포트 2분할(고르는 곳 ↔ 보는 곳)이므로 한 앱 안에서 섞어도 문법이 충돌하지 않습니다.

### 결합 제안

상단 단계 전환은 A의 3단계 세그먼트를 씁니다. 단계가 늘어나면 C의 접힌 띠(단계마다 상태 표시)로 바꿀 수 있습니다.

| 단계 | 구성 |
| :--- | :--- |
| 입력 | A의 좌우 병치. 거리 행렬과 시리즈 225행처럼 대량 편집이 필요한 탭에서만 왼쪽 폼을 E식 격자로 바꿔, 엑셀 숙련자의 대량 입력을 지원합니다. |
| 결과 확인·수정 | B의 목록 + 상세 + 인스펙터. 시즌 전체를 보는 개요가 B의 약점이므로, 상세 영역의 "개요" 레코드에 D식 한 줄 타임라인(슬롯 + 위반 트랙)을 넣어 보완합니다. |
| 시즌 운영 | B의 "경기 기록 / 재편성" 레코드 유형에, A식 오른쪽 수용 게이지를 붙입니다. |

D(레이어 타임라인)는 단독 앱으로 쓰기보다 일정 골격 입력의 미리보기와 시즌 운영의 개요 띠로 넣는 것이 가장 효과적입니다. E는 엑셀 사용자 비중이 매우 높고 대량 붙여넣기가 주 업무로 확인되면 1순위 후보로 다시 검토할 만합니다.
