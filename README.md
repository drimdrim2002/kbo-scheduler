### ④ 구단 지표 대시보드 (`app/studio/step-quality.js`)

```
┌ 평균 이동거리 ─┬ 허용 범위 초과 구단 ──┬ 가장 큰 편차 구단 ┬ 주말 홈 편차 ┐   ← 카드 4개
│ 7,346.5 km     │ ▲ 6 구단 (이동거리)    │ LG −990.2km       │ 1 시리즈 차이│
│ 최다 [롯데] 최소[LG] │ [SSG][두산][LG]…  │ 허용 범위 밖 690.2 │ 최다 12·최소 11│
│ KT 7,466.2 · +119.7 │ KT 범위 안        │ KT +119.7km       │ KT 12시리즈  │   ← 선택 구단 줄
├ 총 이동거리 (막대) ──────────┬ 이동 횟수 (점) ──────────────┤
│ 평균 점선 · ±300km 띠 · 초과 빗금 ▲ │ 평균선 · ±2회 띠 · 초과 ▲       │   ← 차트 2×2
├ 휴일 가중치 (점) ────────────┼ 주말 홈 (점, 참고) ──────────┤
├ ▸ 구단 지표 비교표 │ KT 이동거리 7,466.2km · 이동 ▲38회 · …   표 펼치기 ┤   ← 접힌 띠(한 줄 요약)
└──────────────────────────────────────────────────────────┘
펼치면: 카드 4개 / 차트 1×4 띠(높이 196, 1800 이상 250) / std 비교표 전체(띠 안에서 세로 스크롤, 선택 행이 보이게 맞춤)
```

- **카드 값**(`S.metricsSummary()`)은 모두 `core/score.js`의 `teamMetrics`와 `league`에서 계산한다.
  - 평균 이동거리 = `league.meanDistanceKm`. 리그 합계는 `league.totalKm`. 최다·최소 구단은 칩으로 보인다.
  - 허용 범위 초과 = `overDistance` 구단 수(이동거리 평균 ±300km 밖). std의 단계 요약 "거리 허용오차 초과 6구단", 목록 배지 ⚠6과 같은 값이다. 옆에 이동 횟수·휴일 초과 수도 적었다.
  - 가장 큰 편차 = |이동거리 − 평균|이 가장 큰 구단. 부호와 함께 보이고, 허용 범위를 얼마나 넘었는지도 적는다.
  - 주말 홈 편차 = 주말 홈 시리즈의 최댓값 − 최솟값(참고 지표).
- **선택 구단 강조**: 카드의 구단 칩, "가장 큰 편차" 카드 전체, 막대, 점, 표 행이 모두 std의 `data-act="q-team"`을 쓴다. 한 곳을 누르면 다음이 함께 바뀐다.
  - 막대 1개와 점 3개(남색 고리)
  - 칩(남색 채움)
  - 카드마다 맨 아래의 **선택 구단 줄**(예: `KT 범위 안 (평균 대비 +119.7km)`)
  - 접힌 띠의 한 줄 요약, 펼친 표의 행
  - 오른쪽 구단 카드
- **차트**: `app/studio/viz-metrics.js`를 그대로 쓴다. `S.mchart.dotRows`에 `bare` 옵션을 더해 지표 하나짜리 점 차트를 그린다. 이 차트에는 줄 제목·왼쪽 여백이 없고, 아래에 눈금, 위에 평균을 적는다. `distanceBars`에는 `ticks: false`(펼친 띠의 좁은 막대용)와 `tickN`을 더했다. 차트 상자 크기는 렌더 후 재서(`after()`), 그린 크기와 4px 넘게 다르면 한 번 더 그린다. 창 크기를 바꿔도 다시 그린다.
- 일반 모드에는 코드가 없다. 개발자 모드에서는 카드·차트 머리글에 `S1`·`S2`·`S3`·`S4` 배지가 붙는다. 표 머리글은 std처럼 `(S1~S3 분산 대상)`이다.
- 목록 이름은 "구단 지표 비교표"에서 **"구단 지표 대시보드"**로 바꿨다. 주소는 `qv=metrics` 그대로다.

### ② 큰 선택 카드 (`app/studio/step-review.js` `S.reviewSimpleOptions`)

- **실행 시간 카드 3장**(빠르게 1분 / 보통 5분 / 충분히 30분)에는 다음이 들어 있다.
  - 60분 눈금판 그림: 실행 시간만큼 부채꼴을 칠한다(1분 6°, 5분 30°, 30분 180°)
  - 큰 시간 글자
  - 꼼꼼함 막대(1~3칸)
  - 예상 끝: `최대 5분 · 더 나아지지 않으면 1분 15초 뒤 끝`. 개선 없음 종료 시간은 std 동작 `run-time`과 같은 `max(15, 시간/4)`로 계산한다
  - **언제** 한 줄: `평소 편성안을 만들 때 (대부분 충분)`
- **시작 방식 카드 2장**에는 그림과 설명, **언제** 한 줄이 들어 있다. 다듬기 그림은 채운 칸을 맞바꾸는 화살표, 새로 짜기 그림은 빈 칸과 고정 칸, 다시 짜기 화살표다.
- 카드 아래에 한 줄 요약이 있다: `빠르게 1분 · 지금 일정 다듬기로 시작합니다. 고정한 경기 5개는 그대로 둡니다.` 그 아래 **편성 시작** 버튼은 높이 44px로 키웠다.
- 데이터는 `S.TIME_PRESETS`·`S.INIT_MODES`에 `when`(언제 쓰나요)과 `depth`(꼼꼼함)를 더했다. 동작(`run-time`·`solver-init`), 클래스(`.choice`, `.on`, `role=radio`, `aria-checked`)는 std와 같아서 std 점검을 그대로 통과한다. 편성 중 화면과 개발자 옵션은 std와 같다.

## 알려진 빈틈

- 차트 크기는 렌더 후 잰 상자 크기로 맞춘다. 헤드리스 `--screenshot`처럼 창 크기가 바뀐 뒤 렌더 기회가 없는 환경을 대비해 `resize` 때 바로 다시 그린다.
- 주말 홈 편차 카드는 동률 구단이 많아(최다 12 = 5구단, 최소 11 = 5구단) 구단 칩 대신 구단 수만 적었다. 이름은 카드 `title`에 있다.
- 펼친 상태의 이동거리 막대(1440 폭 약 200px)는 눈금 글자를 지웠다. 막대 끝 값과 평균 글자로 읽는다.
- 실행 시간 카드의 꼼꼼함·예상 끝은 설명용이다. 편성 실행은 std처럼 목업이라 실제 탐색 시간은 바뀌지 않는다.

## 1. 개요

alt-a 편성 스튜디오를 골격으로 확정하고(W14), 단계별로 다른 후보의 요소를 가져와 다음 여섯 가지를 바꿨다. 나머지 화면·메뉴 위치·시각 톤은 alt-a 그대로다.

| # | 바꾼 곳 | 내용 |
| :--- | :--- | :--- |
| 1 | 전체 | 일반 용어로 바꿨다. Hard/Soft, 규칙 코드(H0-b …), 원점수는 설정의 **개발자 모드**를 켰을 때만 보인다(W16) |

## 3. 일반 모드와 개발자 모드

- **설정 → 기능 탭 맨 위**에 `개발자 모드` 스위치가 있다. 값은 이 브라우저의 localStorage `kbo-wizard:opt-2:dev`(std는 `kbo-wizard:std:dev`)에 저장하고, 기본은 꺼짐이다. 주소에 `dev=1` 또는 `dev=0`을 붙이면 그 탭에서만 강제로 켜거나 끈다(스크린샷용).
- **일반 모드**: 개발자용 요소를 숨기는 데 그치지 않고 **DOM에 만들지 않는다**. 자가 점검이 50개 화면의 `textContent`와 `title`·`aria-label`을 검사해 금지어가 없음을 확인한다. 금지어는 `Hard`, `Soft`, `hard/`, `H0-`, `H1`, `S0`~`S4`, `RH-`/`RS-` 코드, `BendableLongScore`, `[-2/-1]` 같은 원점수 꼴이다.
- **개발자 모드**에서는 일반 용어 옆에 다음이 함께 보인다.
  - `필수 규칙 위반(Hard) 3건`
  - 규칙 코드 배지: `H0-b 한 구장에 두 경기`
  - 상단 원점수 `[-2/-1]hard/…soft`
  - Δ 수치: `Hard +1 해소 · Soft +489,287`
  - ② 개발자 옵션: 최대 시간, 개선 없음 종료, 시드, 초기해, 개선 횟수, Hard/Soft 현재 최고, 원점수, 점수 추이 차트
  - ④ 공정성 점수 구성의 공식과 원점수
- 코어·공통 모듈이 만든 문장에는 코드가 들어 있다. 예: 사전 점검 `미배정(S0)이나 …`, `H0-d 위반 유지`. 이런 문장은 `S.plain()`이 일반 용어로 바꾼다. 패널 제목·설명(`S.paneHead`)과 토스트(`S.toast`)는 모두 이 함수를 거친다.

| .xlsx 업로드·구글 시트 읽기 | 미리 준비한 미리보기를 띄운다(오류 2건). "가져온 뒤" 시각화도 미리 정한 변경으로 그린다(`S.importAfter`). 슬롯 2개, 시리즈 3행 변경, 1행 추가, 1행 삭제, 공휴일 6/3을 반영한다 |
| 편성 실행 | 정해 둔 진행률을 약 6초에 재생한다. **실행 시간 프리셋과 상관없이** 재생 시간은 같고, 표시되는 경과 시간만 프리셋을 따른다. 배정은 바꾸지 않는다 |
| 재편성 탐색 | 대상 계산과 탐색은 실제 코어를 쓴다. 실행 시간만 연출이다 |
| .xlsx 내보내기·빈 양식, REST 엔진·Kakao | 토스트로 알리거나 설정 값만 저장한다 |

다음은 목업이 아니다. 규칙으로 초안 만들기, 구단쌍 규칙으로 만들기, 입력 결과 시각화, 이동 경로 재생은 실제 데이터로 계산한다.

## 10. 점검 결과

- **페이지 스크롤**(`tools/studio/checkall.sh`, 경로 `tools/studio/routes.txt`): 32개 경로 × 2크기(1440×790, 1920×970) = 64건이다. 모두 페이지 스크롤 0, 콘솔 오류 0, 허용하지 않은 두 방향 스크롤 0이다.
- **자가 점검**(`tools/studio/selftest.sh`, `?selftest=1`): 49개 모두 통과했다(1440·1920 모두). alt-a의 29개에 다음을 더했다.
  - 편성 중에는 옵션 대신 진행 막대·경과 시간·상태 문장만 보임
  - 일반 모드에 개발자 옵션 없음
  - 실행 시간 프리셋 → `timeLimitSec`(300·1800), 시작 방식 → `init`
  - 개발자 모드 켜기(Hard/Soft·원점수·개발자 옵션·점수 추이) → localStorage 저장 → 끄기(사라짐)
  - 시리즈 셀 편집 → 행렬 칸 값 변경, 바뀐 칸 2개 강조, 합 ≠ 15 표시 → 실행 취소 → 복귀
  - 슬롯 선택 → 시즌 띠 강조
  - 가져오기 미리보기 시각화(시리즈 행렬, 슬롯 띠)
  - 지표 차트 클릭 → 표·막대·점 3줄 모두 같은 구단 강조, 키보드 Enter 선택
  - 이동 경로 재생 → 정지 → 타임라인 칸으로 위치 이동 → A6 끄면 탭 제거
  - **일반 모드 금지어 검사**: 50개 화면에서 금지어가 없어야 한다. 대상은 ① 시트 8개·한 건 편집, 가져오기 3종의 시트별 미리보기, 구글 시트, ② 일반·차단·편성 중, ③ 위반별·시리즈·빈 인스펙터·슬롯 목록·구단×슬롯·스냅샷 메뉴·데이터 메뉴, ④ 보기 13개와 공정성 단계 5개, 시즌 운영 3탭과 재편성 묶음, 설정 3탭이다. 선택 기능은 모두 켠다.
  - 검사기 자체 확인: 개발자 모드에서는 같은 검사가 코드를 잡아야 한다
- 1800px·900px 구간이 바뀌면 다시 그린다(창 크기 변경 대응). 그래서 1920 스크린샷의 차트·달력도 970 높이 기준으로 그려진다.

## 12. 알려진 빈틈

- 편성 실행은 목업이라 실행 시간 프리셋이 실제 탐색 시간을 바꾸지 않는다. `timeLimitSec`·`unimprovedSec` 값만 바뀐다.
- 가져오기 미리보기의 "가져온 뒤" 그림은 xlsx·구글 시트에서는 미리 정한 변경이다. 보조 생성 두 가지만 실제 생성 결과다.
- ① 구단과 거리 탭에는 입력 결과 그림을 더하지 않았다. 본문에 이미 지도와 히트맵이 있다.
- 이동 경로의 재편성 구간은 시즌 운영에서 재편성을 실행한 뒤에만 나온다. 묶음마다 첫 경기 날짜로 한 구간을 만든다. Kakao 지도 모드는 지원하지 않는다(내장 SVG만 쓴다).
- 점 차트에서 같은 값에 구단이 몰리면 이름이 위아래 여러 줄로 쌓여 옆 줄과 가까워진다. 1440×790의 이동 횟수·주말 홈 줄이 그렇다.
- ④ 상대 매트릭스(A5)와 거리 히트맵은 alt-a의 공통 `KBO.Chart.heatmap`을 그대로 쓴다. 중간 단계 칸의 흰 글자 대비가 AA(4.5:1)에 못 미칠 수 있다. 새로 만든 ① 구단쌍 행렬은 6~8 칸에 남색 글자를 써서 4.9:1을 맞췄다.
- 일반 모드 검사는 화면에 그려진 DOM만 본다. 토스트는 자가 점검 중 끄므로 `S.toast`의 `S.plain` 변환으로만 막는다.
- alt-a에서 이어받은 빈틈: 드래그 중 Δ 미표시, 가져오기 배정 초기화는 확인만 받음, 새로고침하면 시연 초기 상태로 돌아감.
