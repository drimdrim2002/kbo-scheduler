# alt-a 편성 스튜디오 (Scheduling Studio)

> 브랜치 `wizard-ui/alt-a` · 요구사항 `KBO_WIZARD_UI_REQUIREMENTS.md` §8 alt-a · 진입점 `index.html` (`file://`로 바로 열림)

## 1. 콘셉트

상단 가로 스테퍼(① 데이터 준비 → ② 검토·실행 → ③ 결과·수정 → ④ 품질·배포) 아래에 모든 단계가 **목록 · 본문 · 인스펙터 3분할**이라는 같은 문법을 쓴다.

- **왼쪽 목록**은 하위 항목이다. 단계마다 시트, 점검 항목, 위반과 구단 필터, 품질 보기와 구단이 들어간다.
- **가운데 본문**은 주 화면 하나다. 시트 표, 엔진, 달력, 차트 가운데 하나를 띄운다.
- **오른쪽 인스펙터**는 선택한 행·시리즈·위반의 상세다. 편집 필드, 핀, 이동 후보와 Δ가 여기에 있다. 인스펙터는 접을 수 있다.

Linear·Jira·Figma 속성 패널 같은 업무 도구가 기준이다. 위반 → 원인 → 조치 루프가 가장 짧다. 왼쪽에서 위반을 누르면 달력이 그 달로 가서 해당 시리즈를 강조한다. 인스펙터에는 원인과 실제 채점기로 계산한 조치 후보 5개가 Hard/Soft Δ와 함께 나오고, `적용` 한 번으로 고친다. 실행 취소도 할 수 있다.

## 5. 데이터와 가상 위반

- 데이터는 `core/preset-2025.js`의 2025 실제 값(구단 10, 슬롯 45, 시리즈 225, 거리 행렬)이다. 점수·위반·지표는 모두 `core/score.js`로 계산한다.
- 결과 화면을 보여 주려고 **가상 위반 3건**을 넣었다. 셋 다 채점기가 실제로 찾아내고, 화면에 `가상` 표시가 붙는다. 점수는 `[−2/−1]hard`이다.
  - H0-f: 시리즈 #88(KIA–KT)의 홈·원정을 뒤집어 KT 원정 4연속(5/13~5/23)이 생긴다.
  - H0-b: 시리즈 #75(LG–삼성)의 홈·원정을 뒤집어 5/9(금) 잠실에 두산·LG가 동시에 홈이 된다.
  - H1: 3/25 슬롯과 5/27 슬롯을 맞바꿔 5/30 롯데·SSG 대진이 연속된다.
- 스냅샷 `엔진 1차 결과 — 슬롯 교환 전`을 복원하면 H1이 해소된다. 각 위반에는 조치 후보가 있다. 예: 홈·원정 되뒤집기, 슬롯 맞바꾸기.
- 기준일은 2025-07-10이다. 그 이전 경기는 `완료`로 기록했고, 5경기를 `취소`했다(우천·미세먼지·폭염). 7/8~7/9는 `결과 미입력`으로 남겼다.

## 6. 목업인 것 (화면에 점선 `목업` 표시)

| 기능 | 시안 동작 |
| :--- | :--- |
| .xlsx 업로드·구글 시트 읽기 | 미리 준비한 미리보기를 띄운다. 시트 7개에 오류 2건(`시리즈 · 12행 · B열(원정): 알 수 없는 구단 'LGG' — 'LG'인가요?`, `이벤트 · 8행 · C열(날짜)`)이 있다. 적용하면 자동 스냅샷을 저장하고 공휴일·경기없는기간 시트를 실제로 반영한다. 배정 초기화는 확인만 받고 실제로는 초기화하지 않는다(시연 유지). 실행 취소할 수 있다 |
| .xlsx 내보내기·빈 양식 | 토스트로만 알린다. 프로젝트 JSON·엔진 JSON·일정표 CSV는 실제로 내려받는다 |
| 엔진 실행 | 정해 둔 진행률(가상 60초를 약 6초에 재생), 점수 추이, 입력 잠금(`app.guard`가 실제로 막음)을 보여 준다. 끝나면 ③으로 간다. 배정은 바꾸지 않는다 |
| 재편성 | 대상 계산(`computeTargets`)과 탐색(`Reschedule.createSearch`)은 실제 코어를 쓴다. 실행 시간만 연출이다 |
| REST 엔진·Kakao | 설정 값만 저장하고 연결 시험은 하지 않는다 |

규칙으로 초안 만들기와 구단쌍 규칙으로 만들기는 목업이 아니다. 실제 생성기 결과를 현재 데이터와 비교해 같은 미리보기로 보여 준다.

## 9. 강점과 약점

강점

- 위반 → 원인 → 조치가 한 화면에서 끝난다. 조치 후보와 Δ는 실제 채점기 값이고, 적용과 실행 취소가 즉시 된다.
- 네 단계와 시즌 운영이 모두 같은 3분할 문법이라 한 번 익히면 길을 잃지 않는다. 설명은 패널 머리의 한 줄뿐이다.
- 시트 표가 엑셀과 같은 행 번호·열 문자를 쓴다. 그래서 가져오기 오류 위치(`시리즈 · 12행 · B열`)와 화면 위치가 그대로 맞는다.
- 달력은 날짜 칸이 아니라 슬롯 띠로 그린다. 그래서 같은 대진을 사흘씩 반복해 그리지 않고, 1440 폭에서도 한 달이 스크롤 없이 들어간다.

약점

- 정보 밀도가 높아 처음 쓰는 사람에게는 빽빽하다. 1440×790에서 6주짜리 달(6월)은 시리즈 줄 높이가 약 14px까지 줄어든다.
- 인스펙터가 늘 폭 320px를 차지한다. 그래서 1440에서는 본문이 약 890px로 좁다. 접을 수는 있지만 기본은 펼침이다.
- 같은 3분할을 모든 단계에 강제한다. 그래서 ② 검토·실행처럼 인스펙터에 쓸 정보가 적은 단계에서는 오른쪽이 비어 보인다.
- 차트는 공통 `KBO.Chart`를 다시 칠한 것이라 표현력이 제한적이다. 예를 들어 막대 차트의 허용오차 라벨이 막대에 겹칠 수 있다.

## 10. 파일

| 파일 | 내용 |
| :--- | :--- |
| `index.html` | 진입점. 코어·공통 컨트롤러(`app/common/app.js`, `dom.js`)와 스튜디오 스크립트를 classic script로 읽는다 |
| `app/studio/studio.css` | 시각 언어 전체(토큰, 3분할, 표, 달력, 차트·지도 색, 오버레이) |
| `app/studio/base.js` | 아이콘, 포맷, 기능 레지스트리(`Studio.feature(id)`), 가상 위반 시드, 라우터, 스크롤 점검 |
| `app/studio/shell.js` | 상단 띠, 스테퍼, 이전/다음, 메뉴, 렌더 루프, 이벤트 위임 |
| `app/studio/step-data.js`, `import.js` | ① 시트 표·한 건 편집·시즌 골격·구단과 거리, 가져오기 미리보기 |
| `app/studio/step-review.js` | ② 사전 점검·엔진(목업 실행) |
| `app/studio/step-result.js` | ③ 달력·위반·인스펙터·이동 후보 Δ·스냅샷·드래그 |
| `app/studio/step-quality.js` | ④ 지표·Soft·차트·일정표·내보내기 |
| `app/studio/ops.js`, `settings.js` | 시즌 운영, 설정 서랍 |
| `app/studio/selftest.js` | `?selftest=1` 상호작용 자가 점검 |
